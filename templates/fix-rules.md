# 修正規則（給修正代理）

> 依評等分三種回合：X 立即修 → B 小修 → C 重寫。每個回合都由「修正代理」照本檔改、「審查代理」用 `prompts/content-reviewer.md` 的 prelaunch 模式獨立審，最後由協調者同步與上線。
> 你只改分配給你的檔案；不做版本控制操作、不部署、不改清單以外的檔案、不跑任何產生器或發布腳本。

## 0. 每一回合共通

- 先讀：該篇的審稿評語（`out/batch-NN.md` 中的段落與 `ISSUE` 行）、`07-content-writing-standard.md` 的禁止清單與用詞表、事實表 `.seo-agent/data/content/facts.md`、CTA 路由表 `cta-map.md`。
- 不准動：網址、canonical、datePublished、圖片、版型骨架、別組的檔案、使用者指定的禁區主題。
- 同一頁若有多份副本（無副檔名版、鏡像頁），你只改主檔，副本交給協調者同步。
- 不新增未經查證的事實；不為湊字數加空話。刪掉後段落變短沒關係，但要讀得通、前後銜接。
- 產品說法照真相順序核對：實際走一遍流程 > 程式裡會執行到的設定與價格常數 > 價格頁與條款 > 介紹頁。介紹頁寫的不能當依據（`07` 第 4 節）。
- 寫在地語言的自然口語（繁中用台灣用語），不寫 AI 套話。
- 看到不在你這組範圍、但一定要處理的問題（全站模板、別人的頁、會蓋回修正的腳本），只記進剩餘問題清單 `leftovers.tsv`，不要順手改（格式見 `08` 步驟 B 第 4 點）。
- 每篇改完跑檢查（第 4 節），寫修正紀錄（第 5 節），交件前照第 7 節自查。
- 長度規格只有一套，以 `09` 第 3 步為準：`<title>` 連同尾端品牌 ≤32 個全形字；描述 50–80 個全形字（英文約 120–155 字元）。

## 1. X 立即修（只把錯的、不該有的拿掉或改對；不整篇重寫）

處理範圍：評語標 X 的每一點；評語指出的任何事實錯誤（即使沒標 X）；全篇再掃一次，包含 FAQ、meta、og、twitter、title、JSON-LD。

| X 代碼 | 怎麼改 |
|---|---|
| `fake_expert` | 純故事段落刪除；有教學用途的改成假設情境「例如：如果你…可以先…」，不宣稱真實發生、不暗示應驗；第一人稱真人口吻（「我相信」「在我的諮詢中」）改成中性第二人稱；全站共用的假人設小標要「每篇依內容自己改寫」或整段刪，不要全站換成同一句。標題層（title、H1、og、twitter、headline、描述）的假人設與保證字樣最容易漏，掃描字典見 `07` 第 6 節 |
| `guarantee_or_blame` | 「一定、精準、準確度極高、只要誠心就準」刪掉或改成誠實說法；「情緒低落會抽到壞牌」改成「情緒會影響你怎麼解讀，不會改變結果，平靜後再看」 |
| `self_undermining` | 「AI 比較表面、手動比較準、去找真人／付費比較準」改成中性準確的說法（例：線上一樣是隨機抽出，AI 依你的問題與結果說明，重點在問題問得具體）；不要反過來吹捧 |
| `wrong_product_claim` | 不存在的服務（「一次解讀 30 分鐘」「可隨時跟老師互動」）刪除；情境錯置（線上工具寫「預約時當面問」「切忌重複洗牌」）改成產品實際的流程；功能、價格、免費條件照真相順序改成和實際流程、程式碼或價格頁一致 |
| `ymyl_advice` | 刪具體判斷（懷孕、病況、官司勝負、何時加碼停損、買哪一檔），改寫界線：只能幫你整理想法；健康找醫師、法律找律師或法律扶助、投資看財務資料或找合格顧問 |
| `boundary_violation` | 拿結果指控他人、介入他人關係、接觸對方家人等改成尊重界線的建議；有安全疑慮時給在地求助資源 |
| `nonexistent_entity` | 換成意思相符的真實實體（名稱寫對）或刪句；編號、張數、位置照事實表 |
| `wrong_fact` | 改成唯一正確說法（塔羅：正逆位就是抽出時的方向；凡教看表情、看周圍、憑感覺者全部改正） |
| `external_brand` | 外站品牌、作者名、抄來的標題格式、hashtag 標題改成本站自然標題；推薦競品刪除；編造的參考資料刪除 |
| `broken_artifact` | 佔位小標改成有意義的小標；`[[slug:文字]]` 改成正常連結（slug 存在才連，否則留純文字）；簡體、外文、亂碼、斷句、生成指令外洩（「插入實例：」「本文規劃將回答」）、殘留標籤（`<context>`）、brief 外洩（受眾設定）都修好 |

FAQ 要同時改兩處：畫面的 FAQ 區塊與 FAQPage 結構化資料；刪題就兩處都刪。結構化資料裡的每一題都必須逐字出現在畫面上（上線門檻），JSON 必須仍可解析。既有模板的題數本來就差一題（例：畫面 6 題、結構化資料 5 題，每題都在畫面上）時，不在 X 回合硬補，記成 should_fix 交給產生器。meta、og、twitter 描述有問題一起改（50–80 個全形字、通順、不灌關鍵字）。

改了 `<title>`／H1／og:title／headline 的，一律在紀錄寫「舊標題 → 新標題」，並登記到標題帳本 `.seo-agent/data/content/title-changes.csv`（slug、舊標題、新標題、誰改的、哪一回合）；協調者會照它同步全站引用。

## 2. B 小修（局部修；不動 title、H1、描述）

- 「重點摘要」照抄描述 → 改成正文真正的 2–3 個重點（短句）；頁首已有 tldr 時可整框刪除。
- 人名、系統名點名 → 最多留一處且跟上下文有關；參考資料區與結構化資料的實體欄位不在本回合範圍（記進 leftovers，交給下一回合）。
- 同一篇重複連同一個目標 → 只留第一處。
- 用詞照正式名表統一；英文殘留改成正式中文名；用字與標點照 `07` 第 7 節（回饋、「」、全形？、你／妳不混用）。
- 評語說「該用表格」→ 改成表格（`<table><thead><tbody>`，外包 `overflow-x:auto`，沿用站內既有樣式，不新增 class）。
- 補評語要求的一次完整示範（題目 → 實際內容 → 怎麼串讀 → 變成什麼行動）。
- CTA 指向不存在的功能或不對題 → 依 CTA 路由表（`.seo-agent/data/content/cta-map.md`）改成對題、存在、點下去就能開始的頁；路由表沒有合適去處時列 `decide`，不要自己發明。CTA 連同前後兩句一起讀，不能讓人以為站上做得到其實做不到的事。
- 延伸閱讀：只替換「已轉址」或「主題明顯不相干」的目標；說明句改成描述被連頁「現在」的內容（目標頁同一輪也在重寫時，等它定稿再寫）；新目標必須存在、沒有轉址、不在排定 301 的清單上。
- 禁用詞連小標也要改（例：投資字眼「停損」在感情文的小標改成「放手標準」）。
- 界線句勸退產品的核心動作時（例：「不要短時間重複占卜」），改成說明什麼時候值得再問。

## 3. C 重寫（保留網址，整篇換內容）

- 先寫重寫規格（`data/content/rewrite-specs/<slug>.md`：意圖、核心答案、H2 大綱、表格、示範、FAQ、要吃下的查詢詞、要搬進來的被轉頁段落），審過再寫入頁面。
- 只重寫：開頭、正文、文末 CTA、FAQ（畫面＋結構化資料）、延伸閱讀說明句、描述 4 處（meta、og、twitter、BlogPosting，50–80 個全形字）。版型骨架、日期、網址、canonical、封面、麵包屑路徑、頁尾不動。
- 開頭前三行直接回答；整篇照 `07` 的每篇必備 9 條；FAQ 5 題、第一句就答；畫面和結構化資料的題數、題目、答案、順序完全一致。
- 標題要改的：`<title>` 連同尾端品牌 ≤32 個全形字；9 處同步（title、og、twitter、headline、keywords、麵包屑名稱、H1、封面 alt，以及頁首關鍵字列——它是內部欄位外洩，應從模板移除，移除前才同步），記錄舊→新並登記標題帳本。
- 產品說法照真相順序逐句核對（例：「不用註冊就能看完整解讀」若程式要求登入才看全文，就要改成「先讀開頭，登入後看完整解讀」）。
- 有合併計畫的主文：把被轉頁在接的查詢詞寫進標題、H2 或 FAQ；把評語指定的段落搬進來；成員之間定義不同（牌位、步驟）時，先照正式工具頁統一。
- 新增的內連只連「保留頁」（不在轉址清單、不在已轉址清單）。
- 「閱讀 N 分鐘」與 wordCount 依新篇幅重算（中文約每分鐘 350 字）。

## 4. 每篇改完的檢查

- 禁用詞與模板句掃描（`node scripts/content-audit.mjs` 只掃本篇，或站內自備檢查腳本）。
- HTML 結構與原檔比對：不可多出新的結構錯誤（移除殘留標籤造成的差異屬預期，要在紀錄說明）。
- `<table>` 數等於外層捲動容器數。
- 結構化資料可解析；FAQ：結構化資料的每一題都逐字出現在畫面上；新寫與重寫的頁，題數、題目、答案、順序完全一致。
- **內容刪了、改了，隱藏欄位要跟著改。** 刪掉畫面上的參考資料區，就同時刪 JSON-LD 的 citation；拿掉人名堆砌，就同步改 about；重寫後要更新 wordCount 和閱讀時間。案例站 C 回合有一篇：畫面上的參考資料區已經刪了，JSON-LD 還留著 3 筆 citation，about 還列著被刪掉的人名，wordCount 也是重寫前的舊值。
- 描述 4 處一致；改標題時 9 處一致。
- 站內連結目標都存在、沒有經過轉址。
- 事實（實體編號、張數、位置）對照事實表；求助資源只用白名單。
- canonical、og:url、圖片、日期、CTA 區塊（B／X 回合）沒有變。
- **先找出被測試鎖住的字串。** 前幾波常用測試鎖住頁面上的特定文字、連結數或位置，例如某篇「重點摘要」要接原本的導言、某類頁開頭恰好 1 條 hub 連結、某句界線句必須存在。開工前，在測試資料夾搜本批的 slug，列出受保護的字串。修正時保留它們，或連同測試一起改，並在紀錄寫明理由。案例站一篇「重點摘要」被改寫，部署 CI 的舊測試就失敗，會擋住整批上線。

## 5. 修正紀錄格式（每篇一段，追加到 `data/content/<日期>-fixlog/<組名>.md`）

```
### <slug>
- 檢查：OK（或：誤報＋原因）
- 處理的問題：1) … 2) …
- 改動（去掉 HTML 標籤後的文字）：
  - 原：「…」→ 新：「…」
  - 刪除：「…」（理由）
- 標題變更：舊 → 新（已登記 title-changes.csv）（若有）
- 延伸閱讀替換：舊目標 → 新目標（理由）（若有）
- 碰到的受保護字串或測試：…（若有，寫保留或怎麼一起改）
- 組外問題：已寫進 leftovers.tsv（scope）（若有）
- 未處理／需人決定：…（附建議）
```

回合結束回報：處理篇數、檢查是否全數 OK、標題變更清單（和標題帳本一致）、改過的檔案清單（給協調者同步副本）、新增的 leftovers、需人決定的事。

## 6. 協調者在每回合後要做的事

- 同步副本（無副檔名版、鏡像頁）並跑「副本逐位元相同」檢查。
- 傳播標題變更：照 `08` 決策規則 6 做——以標題帳本為準、先查三種碰撞（新標題包含舊標題、兩頁舊標題相同、舊標題藏在描述或 CTA 裡）、以 slug 定位欄位寫入，不要全站子字串取代；範圍包含延伸閱讀與內文錨文字、CTA 句子、列表、分類、ItemList 描述、sitemap 圖片標題、llms 文件與內部資料檔。驗收：舊標題連同變體殘留為 0、替換腳本重跑零變更、sitemap 通過 XML 驗證、JSON-LD 全部能解析。
- 重建列表頁與分類頁的描述（不只標題）；重建完成後才驗收，不要邊重建邊驗。
- 在已同步副本的暫存複本跑完整部署測試，不能只跑單篇檢查。副本沒同步時，「兩份逐位元相同」這類測試會失敗；案例站有 2 組測試因此誤報。
- 更新剩餘問題清單：各組新增的項目歸類到 scope，已解決的改 fixed；上線前 `danger` 與 `propagation` 的 open 必須是 0。
- 收齊「需人決定」，依 `templates/review-rubric.md` 第 4 節的 8 類整理成一份，每條附預設建議給使用者。
- 上線後送 IndexNow、重新提交 sitemap、`log-change.mjs` 記 D0。

## 7. 修正代理最常犯的錯（交件前自己先查一遍）

案例站 530 篇次修正，上線前審查抓到的錯，大多出在修正代理「新寫」的地方，不是原文：

1. **新增的表格沒包捲動容器**：67 篇、113 張。交件前用腳本確認「`<table>` 數＝外層容器數」。
2. **只改了導言**：小標、牌位定義、示範問句、描述四處、FAQ 答案還留著舊立場。改完拿舊立場的說法反查全文。
3. **新寫的產品說明不對**：8 處，例如把介紹頁寫的版本當成站上真的能用的、張數算錯、把「先看開頭」寫成「免註冊就能看完整」。產品句一律照 `07` 的真相順序查。
4. **延伸閱讀說明句照目標頁「改寫前」的內容寫**：5 處。目標頁同一輪也在重寫時，等它定稿再寫。
5. **新寫的事實過度概括**：「每張都…」「一定…」改成「大多…」「常見…」；定義要精確，例如要寫「翻開時圖案正立」，不能寫「牌面朝上」。
6. **示範把結果寫成對方心意的定論**：一律寫「可能」「傾向」，並附「對照實際行動」。
7. **新加的警訊清單誤傷自家**：例如把「先免費、之後付費」列為詐騙特徵。改寫成能區分的條件，例如「收費沒有事先講清楚」。
8. **改了標題沒登記**：不管誰改的標題，都要寫進標題帳本（`08` 決策規則 6）。
9. **延伸閱讀換得太多**：只准換「已轉址」或「明顯不相干」的目標，其他維持原樣。

SaaS 例：在說明文章裡新加「常見詐騙手法：先免費試用、再要求付費升級」，就是第 7 點的錯。
