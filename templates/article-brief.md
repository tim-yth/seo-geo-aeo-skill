# 文章 brief 範本

> 每篇新文章或整篇重寫（C 級）都要先填這張表。寫不出「核心答案」或「站內檢查」兩欄就不要開寫。
> 填好的 brief 存到 `.seo-agent/data/content/briefs/<slug>.md`，交給 `prompts/content-writer.md` 使用。
> 長度規格只有一套，以 `references/09-ctr-titles-snippets.md` 第 3 步為準：`<title>` 連同尾端品牌 ≤32 個全形字（英文約 60 字元）；描述 50–80 個全形字（英文約 120–155 字元）；tldr 一句 50–90 個全形字。

```markdown
# Brief：<暫定標題>

## 1. 意圖與答案
- 暫定標題（`<title>` 連同尾端品牌 ≤32 個全形字；前 12 字放主要意圖詞）：
- 搜這個的人要什麼（一句話）：
- 核心答案 tldr（一句 50–90 個全形字，直接答，不用問句）：
- 描述草稿（50–80 個全形字；每個承諾都對得到內文段落）：
- 讀者真正擔心的事（開頭第一句要碰到它）：

## 2. 關鍵字
- 主關鍵字：
- 別名／俗稱／簡繁寫法／常見錯字（第一次出現時註明，可放進標題）：
- 來源證據（page×query、曝光／排名）：
- 選題來源：GSC 機會詞｜季節題｜種子題｜SERP 建議｜其他

## 3. 站內檢查（必填）
- keyword-map.csv 中這個意圖的指定網址：<無／網址>
- 已在接這組查詢的網址（query-clusters.mjs 結果）：<無／網址＋曝光＋排名>
- 去重：意圖鍵 `主題|意圖|實體`＝；最相近的既有頁＝<網址>，標題相似度＝（≥0.72 視為重複，算法見 `07` 步驟 1）
- 決定：新寫｜改寫既有頁 <網址>｜不寫（理由）
- 會不會跟站內其他頁搶字？如何分工：
- 這篇在接工具意圖的字（「線上」「免費」「直接抽」）嗎？是 → 第一段放工具入口

## 4. 前段對手拆解（serp-snapshot → competitor-snapshot --from-serp；只學結構，不抄句子）
| 手法 | 對手怎麼做（前 5 篇） | 我們現在 |
|---|---|---|
| 開頭 | | |
| 情境與示範 | | |
| 表格／速查表 | | |
| FAQ | | |
| 定位與界線 | | |
| 我們能贏的地方 | | |
- 多數對手都談、我們沒有的子題或實體：要補的｜不補的（理由）
- 讀者會追問的問題（SERP 的問題與討論區塊、GSC 問句查詢）→ FAQ 候選：

## 5. 頁型與必備內容
- 頁型：實體定義｜情境應用｜方法教學｜比較｜是非題｜清單
- 情境（至少 2 個，用「例如／假設」）：
- 表格（哪一張、幾欄）：
- 完整示範（題目 → 實際內容 → 怎麼解讀 → 變成什麼行動）：
- 界線（哪些情況要寫「不能取代專業」）＋在地求助資源：
- 界線怎麼寫才不會勸退產品的核心動作（例：說明什麼時候值得再問，而不是勸人別再問）：
- 時間：常青寫法（不寫「今年只剩…」「本月」）｜存檔頁（月運、年度頁，照該策略處理）

## 6. 事實依據
- 對照事實表 `.seo-agent/data/content/facts.md` 的哪幾條：
- 產品說法的出處，依真相順序：實際走一遍流程（無痕、不登入）＞程式設定與價格常數＞價格頁與條款＞介紹頁
- 有沒有寫到產品沒有的服務型態（情境錯置，例：線上工具寫「預約時當面問」）：
- 參考資料（只放能驗證、跟主題相關的；不放搜尋結果頁、消歧義頁、另一主題的條目）：

## 7. 結構
- H2 大綱（6–8 個；核心答案／怎麼判斷／常見誤解／怎麼做／限制／下一步各一次）：
- FAQ 候選（3–6 題，來自真實查詢與第 4 節的追問，每題第一句就答；畫面和結構化資料用同一份）：

## 8. 導流
- CTA 去處（照 `.seo-agent/data/content/cta-map.md`；路由表沒有的列 decide）：
- 按鈕文字（只用站上存在的功能名）：
- 按鈕旁的條件句（免費範圍、要不要登入，一句話）：
- 點下去幾步能開始？文章教的方法和工具一致嗎（張數、牌位、步驟）：
- CTA 前後兩句讀起來，會讓人以為站上做得到什麼？真的做得到嗎：
- 內部連結 3–5 條（讀者的下一步；目標存在、沒有轉址）：

## 9. 信任與揭露
- 署名：品牌編輯部（連到「內容製作方式」頁）｜具名作者或審訂者（有作者頁才標 Person）
- AI 參與：沒有｜協助起草｜主要由 AI 產生；讀者會問「這是怎麼做出來的」時，在哪裡說明：
- 人工查核人與範圍（含 title、描述、結構化資料、圖片 alt）：

## 10. 不准寫
- X 類別提醒：假專家／編造個案、保證結果、怪罪讀者、醫療法律投資判斷、越界建議、貶低自家產品、外站品牌、不存在的實體、情境錯置
- 標題層也不准有假人設與保證字樣（「專家告訴你」「真實經驗」「一定」）
- brief 本身的內容（受眾設定、寫作指令）不得出現在正文
- 使用者指定的禁區主題：
- 用詞：照站內正式名表；台灣用字與標點（「」、全形？、回饋）
```

## 範例一（塔羅）

```markdown
# Brief：寶劍七在感情裡代表什麼？正位、逆位與該怎麼開口
## 1. 意圖與答案
- 搜這個的人要什麼：抽到寶劍七，想知道對方是不是在騙我、接下來怎麼辦
- tldr：感情題抽到寶劍七正位，常指有人沒把話說完、暗中替自己打算；逆位則是藏著的事慢慢被看見；牌不能當成背叛的證據，判斷還是要回到看得到的互動和彼此的約定。
- 讀者真正擔心的事：「他是不是劈腿？」
## 2. 關鍵字
- 主關鍵字：寶劍七正位、寶劍七逆位；別名：寶劍7
- 證據：寶劍七逆位、寶劍七正位各有數百次曝光，排名 7–8（90 天；數字為示意）
- 選題來源：GSC 機會詞
## 3. 站內檢查
- 已在接的網址：本頁（排名 5–8）、正式牌義頁（牌義泛查詢）→ 本篇只寫「感情」切角，開頭連到正式牌義頁
## 4. 前段對手拆解
| 手法 | 對手怎麼做 | 我們現在 |
|---|---|---|
| 開頭 | 3 篇先講牌面圖案，第 2 段才回答 | 第一句就回答「牌不能當證據」 |
| 表格 | 2 篇有正逆位對照表 | 缺 → 補「曖昧／交往／冷戰 × 正位／逆位」 |
| 我們能贏的地方 | 沒有一篇示範「怎麼把觀察寫成可以說出口的一句話」 | 補完整示範＋讀到一半就能帶著問題抽牌 |
- 對手都談、我們沒有：逆位在「對方坦白」情境的讀法 → 補；牌面的歷史典故 → 不補（離題）
## 5. 必備
- 情境：曖昧、交往、冷戰各一個可觀察的訊號
- 示範：「事實／推測」兩欄清單＋一句可直接說出口的溝通句
- 界線：不能拿牌當指控證據；有暴力或控制時先找現實資源（113、110）；寫「事情有新變化時再問」，不寫「不要再問」
## 8. 導流
- CTA：感情工具頁「先寫下一個具體的問題再抽牌」；按鈕旁：「不用註冊就能先看開頭」；點下去 1 步開始，張數和文章示範一致
## 9. 信任與揭露
- 署名：網站編輯部；AI 協助起草，編輯查核牌義、產品說法、title、描述、FAQ 結構化資料
```

## 範例二（SaaS）

```markdown
# Brief：發票軟體可以自動對帳嗎？哪些帳戶能自動、哪些要人工
## 1. 意圖與答案
- tldr：可以，但只限已串接的銀行帳戶：系統每天自動比對入帳，月底只要處理例外；手動匯入的對帳單、跨幣別收款仍要人工確認。
- 讀者真正擔心的事：月底對帳是不是還要加班
## 3. 站內檢查
- 已在接的網址：功能頁「自動對帳」（排名 6，曝光 1,200）→ 不開新頁，改寫功能頁的開頭與 FAQ
## 4. 前段對手拆解
- 我們能贏的地方：前 5 篇都有比較表，沒有一篇示範「從開立到對帳」的完整流程
## 5. 必備
- 表格：帳戶類型 × 是否自動 × 需要的設定
- 示範：一筆跨月收款從匯入到核銷的完整流程
## 6. 事實依據
- 支援的銀行清單：實際在設定頁走一遍（產品設定頁）；方案限制：價格頁；功能介紹頁寫「所有銀行都支援」→ 不採用
## 8. 導流
- CTA：免費試用頁「用你的銀行帳戶試一次對帳」；按鈕旁：「免費方案可串接 1 個帳戶」
```
