# 變更紀錄（changes.md 每次部署一節）

> 每次部署都追加一節到 `.seo-agent/logs/changes.md` 的最後。非 SEO 的改動、凍結期間的小改、只改設定或環境變數的重新部署、回退本身、外部事件，都要記。
> 先跑 `node scripts/log-change.mjs add`（`--type` 分 seo-change／non-seo-change／measurement／external-event／freeze／rollback）：它會寫入機器可讀的紀錄、算出 D+7／14／28 檢查點，並檢查有沒有和其他波次重疊。
> 再把下面的人工欄位補在同一節。
> **只追加，不改舊節。** 記錯了，就新增一節「更正 <波次 id>」，寫「原本 → 改成 → 為什麼」。

```markdown
## <波次 id>｜<YYYY-MM-DD HH:MM 網站時區>（PT <YYYY-MM-DD HH:MM>）｜<改動名稱>
（<SEO 波次｜非 SEO 改動｜量測｜回退｜外部事件>；只記 D0，不覆寫上方基準）

| 欄位 | 內容 |
|---|---|
| D0 | 部署完成時間：CI「部署」步驟完成的時間，不是 commit 或 push 的時間。只改設定（功能開關、環境變數、CDN 設定）的重新部署也是一次 D0 |
| 排除的 PT 日 | <log-change 產生；部署當地日涵蓋到的 PT 日，整天不列入比較> |
| 版本 | <第一個包含本改動的成功部署：commit 或部署編號> |
| 依據與核准 | <報告或預先登記的路徑>；使用者 <日期> 同意「<原話>」。技術小修註明「技術修正，事後回報」 |
| 類型 | 內容／title 與摘要／內鏈與架構／技術／模板／轉換／量測／版面／設定開關／回退／外部事件；分類：<SEO 增長／SXO 轉換> |
| 頁群與頁數 | <例：器材評測頁群 12 頁；網址清單存 data/<日期>-<id>-urls.txt> |
| 改了哪些欄位 | title／description／H1／正文／FAQ＋JSON-LD／錨文字與連結目標／canonical／hreflang／robots／sitemap lastmod／結構化資料／量測事件／第一屏入口與 CTA |
| 刻意不動 | <觀察中的頁、受保護頁> |
| 間接碰到受保護頁？ | <指向受保護頁的連結數、全站含護欄字的頁數，改前 → 改後；沒有變就寫「無」> |
| 假設與預期方向 | <最多 3 條，對應 wave-record> |
| 主要指標 | <例：處理組 vs 對照組的點擊淨效果；SXO 轉換寫自然搜尋落地 session 的開始率> |
| 護欄 | <查詢（含寫法變體）、範圍、基準、停止線；落地轉換護欄> |
| 影響的追蹤對象 | <頁面、查詢、事件、漏斗步驟：判讀時哪些數字要把這次列為干擾> |
| 所在觀察窗 | <落在哪些波次的窗內 → 判讀只能寫「整體方案效果」> |
| 判讀時要註明 | <同期干擾、定義變更、量測變更、外部事件帳本上的事件> |
| 上線驗證 | 200：<是/否>；新資產版本：<…>；Googlebot UA 下的 title／H1：<…>；煙霧測試：<通過/失敗項> |
| 驗收指令實跑 | <D0 當天用已定稿的舊窗把 D+7／D+28 的驗收指令跑過一次：<通過/失敗與修正>> |
| 通知 | sitemap 重新提交：<HTTP 碼>；IndexNow：<N> 個網址、<HTTP 碼>；GSC 成效圖已加註記：<是/否>；需人工要求索引：<24–48 小時後仍未被抓、又要保留的網址，或「無」> |
| 重抓追蹤 | D+1 lastCrawlTime：<…>（首次被抓時間要在 24 小時內存檔，之後會被覆蓋）；D+3：<…> |
| 驗收日 | D+7＝<日期>；D+14＝<日期>；D+28＝<日期>（資料定稿日由 log-change 計算） |
| 回退方式 | <revert 哪個版本；走正常部署流程；回退本身也要記一節（log-change add --type rollback）> |
```

量測 D0（精簡版；事件、參數、追蹤碼的改動）：

```markdown
## MEAS-<YYYY-MM-DD>｜<改了什麼：例如 頁面語系參數改名 language → page_language／購買事件改由伺服器送>
- D0：<部署完成時間，網站時區＋PT>；版本：<…>
- 改動：<事件、參數、送出位置>；事件字典已更新：<是/否>
- 收件檢查（隔天）：每個自訂參數的非空比例、unknown 占比：<…>；購買逐筆對帳：<N 筆中 M 筆在 GA4、重複 <n>、孤兒 <n>>
- 斷點：<哪些指標從這天起不能和之前比>
```

外部事件（精簡版）：

```markdown
## EXT-<YYYY-MM-DD>｜<事件：例如 Google 核心更新開始／GSC 公告資料異常／他站品牌導航字爆量／廣告重新上線／新的外部引用上線>
- 時間：<PT>（<網站時區>）；來源：<官方公告網址／外聯追蹤表／自己觀察到的數字>
- 影響範圍：<哪些查詢、頁群、國家、裝置；資料異常寫明影響哪些指標（曝光／CTR／名次／點擊）>
- 外部引用另記：<網址、連結屬性（curl 確認）、連到哪一頁、上線當天截圖存放位置>
- 判讀時要註明：<哪些波次的哪個檢查點>；需要另立基準嗎：<是/否>；要改用點擊判讀嗎：<是/否>
```

凍結（開始與解除各記一次）：

```markdown
## FREEZE-<YYYY-MM-DD>｜<開始／解除> 凍結
- 範圍：<受觀察頁群、首頁、核心頁、共用模板、全站 lastmod 重產、指向受保護頁的連結與含護欄字的模板字樣>
- 理由：<正式驗收前／護欄暫停／核心更新進行中>
- 預計解除：<日期或條件>
- 凍結期間允許：只修會擋住使用者的 bug（照樣記 D0）；站外工作（新引用記 EXT）；草稿；傷信任的 X 內容修正（使用者同意、不改網址、不動首頁與共用模板，記 D0 並列為干擾）
```

```markdown
- 舊 runbook 與部署指令：<已標「已停用（日期）＋現行唯一部署方式」>；權杖：<已撤銷／已輪替>
- 現行唯一部署路徑：<…>
```
