# 因果調查報告（流量或排名下滑、暴漲）

> 用在「流量／排名突然變了，要找原因」的時候。全程只讀：不部署、不送 sitemap、不要求索引。
> 重大調查用兩個獨立子代理分別寫這份報告，再互相挑戰（`prompts/causal-investigation.md`）；最後由你整合成定稿版。
> 存成 `.seo-agent/logs/reviews/<日期>-investigation-<主題>.md`。每個數字都要附查詢方式、窗口、是否定稿。

```markdown
# <查詢／頁群> <下滑｜暴漲> 調查｜<日期>｜第 <1｜2｜定稿> 輪｜只讀

## 結論（≤10 行）
1. 發生了什麼（量級、起點、範圍；量級一定寫窗口）：
2. 最可能的原因（信心：高／中／低）：
3. 已排除的原因：
4. 還不能排除的原因：
5. 現在就做（不需要決定的事）：
6. 需要使用者決定的事：

## 1. 資料與口徑
| 項目 | 內容 |
|---|---|
| 新鮮度 | 定稿到 PT <日>（final 與 all 逐日比對確認）；暫定 <日>（只當預警） |
| 時區 | GSC＝PT；GA4＝<屬性時區>；部署＝<網站時區>＋PT；Trends 30 天以上的範圍用 UTC 切日 |
| 口徑 | 精確 query×page／全站 query／頁群；查詢寫法變體合併規則 |
| 排除 | 混合日、爆量查詢、他語言頁、測試流量 |
| 外部事件與資料異常 | <窗內的 Google 更新、GSC 公告的資料異常；碰到曝光記錄錯誤期時，曝光、CTR、名次不可判讀，只比點擊> |
| 證據版本 | <每個被比對的頁面版本號；一律從版本庫取出（git show <版本>:<路徑>），不讀工作樹> |
| 原始資料 | <路徑；每份 API 回應存 request、HTTP 狀態、metadata、抓取時間；SHA-256 清單在 <檔名>；重抓一律開新的日期子資料夾> |
| 定義的官方出處 | <爭點牽涉到的指標定義（曝光、平均名次、跳出率、lastmod、連結報表、Trends 時區）：官方網址、摘錄、抓取時間> |

## 2. 現象（先量清楚，再談原因）
- 精確 query×page 逐日（曝光@名次｜點擊）：
- 改動前的歷史：這個字在這頁以前有沒有曝光？（「回到以前的名次」之前，先確認以前真的有名次）
- 小時資料切段（hourly_all；段落邊界只用部署完成、Google 重抓、外部事件；跨部署的小時整桶排除；個位數到二十幾次曝光的段只記錄；先量事件前的小時波動）：

  | 時段（PT） | 曝光 | 點擊 | 加權名次 | 這段之前已完成的部署／重抓 |
  |---|---|---|---|---|
  | 事件前 3 天（基準） | | | | — |
  | 部署 A 之前 | | | | — |
  | 跨部署 A 的小時 | 排除 | | | |
  | 部署 A 之後、Google 重抓之前 | | | | A |
  | Google 重抓之後 | | | | A＋重抓 |

- 殘留名次（沒有被除名的證據）：
- 承接比例、別頁有沒有接手：
- 裝置、國家、查詢變體、他語言版（合併群組與主語系精確詞分開列）：
- 點擊有沒有同步下滑（排名變差 ≠ 流量下降）：
- 同查詢 CTR、前 10 名天數、固定集合位移：

## 3. 時間線（全部換算成 PT 與當地時間）
| 時間（PT） | 時間（當地） | 事件 | 類型（我方部署／只改設定的重新部署／Google 官方／GSC 資料異常／業界未確認／外部爆量／外部引用上線／廣告／量測） | Google 是否已重抓受影響頁 |
|---|---|---|---|---|
- 斷點前後的無部署區間：<起>～<訖>（用平台部署清單確認，不只看 CI；拿不到完整清單就寫「沒有 CI 部署」）
- 版本重建：斷點前後 <N> 個部署版本中 <M> 個相同，差在 <欄位>（比「上一個正式部署版本 → 這一個」；先正規化換行；確認路由實際送出的是哪一份檔）

## 4. 假設表
| # | 假設 | 驗法（查詢、比對、對照） | 結果（排除／低／中／主因） | 信心 |
|---|---|---|---|---|

## 5. 站內改動的四條件檢核（每個嫌疑改動一列，含間接碰到受保護頁的改動）
| 改動 | ① 早於斷點 | ② Google 斷點前已重抓 | ③ 機制夠強 | ④ 影響範圍＝改動範圍 | 結論 |
|---|---|---|---|---|---|
（四項都成立才能判為成因；只靠時間先後，只能排除「比斷點晚上線的改動」，不能排除較早改動延遲生效，也不能排除其他改動讓下滑持續或加深）

## 6. 對照與安慰劑
- 同群其他頁、同類查詢是否同一天一起動：
- 他語言版／他市場的同類字（只用同一個事件期間的觀察，不要把幾天後的現象拿來支持這一天）：
- 非目標查詢群（例：AI 字 vs 非 AI 字的加權位移）：
- 滾動窗安慰劑（改動前所有同長度窗的分布，觀測值落在第幾百分位）：
- 每個干擾上線的前後 24／48 小時斷點檢查（有沒有新台階）：
- 漏斗階段排除：退步只出現在改動觸發點之前的步驟，就不是它造成的：
- 前人宣稱的數字能不能重現（能／找不到窗口組合）：

## 7. 外部脈絡
- Google 官方更新（狀態頁事件，換算 PT）與 GSC 公告的資料異常：
- 業界未確認的波動（只當背景）：
- 季節性（--yoy；Trends 用同星期組成的窗比日均，排除抓取當天；先對量級）：
- 外部引用與品牌活動（新上線的引用、媒體報導、廣告；品牌與非品牌拆開）：
- 人工 Google SERP（日期、時段、無痕、手機＋桌機；前 20 名、AI 摘要引用了誰、影片、討論區等區塊）：
- 替代引擎 SERP（只當旁證，標 is_google_ranking:false）：
- 競品變化（上線、改版、爆紅）：註冊、存檔、發布、首次索引、排名提升是五件不同的事
```
