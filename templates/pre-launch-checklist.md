# 上線前檢查清單

> 每篇新文、重寫、修正在上線前逐項打勾；整批上線另跑第 B、C 節。
> 任何一項打不了勾，就寫進 `logs/reviews/<日期>-prelaunch.md` 的「需決定」，不要硬上。
> 長度規格只有一套，以 `references/09-ctr-titles-snippets.md` 第 3 步為準。頁面基本功（H1、標題層級、網址、圖片、速度）的細節見 `references/16-on-page-fundamentals.md`；新模板或新頁型另跑 `templates/on-page-checklist.md`，這份清單只留和內容上線直接相關的幾項。

## A. 單篇

### 內容
- [ ] 前三行直接回答標題，或點出讀者真正擔心的事；沒有「本文將…」
- [ ] 標題承諾的內容都有（「對照表」有表、「N 張」真的 N 張、「實戰」有示範）
- [ ] 至少 2 個情境（寫成「例如／假設」，不是真實個案）、一次完整示範
- [ ] 沒有 X 類內容：假專家／編造個案、保證、怪罪讀者、醫療法律投資判斷、越界建議、貶低自家產品、外站品牌、禁區主題
- [ ] 修改後前後一致：導言、H2、FAQ、CTA 的立場相同；拿舊立場的說法反查過小標、表頭、示範、FAQ、描述
- [ ] 界線句沒有勸退產品的核心動作（寫「什麼時候值得再問」，不寫「不要再問」）
- [ ] 沒有寫死當下的相對時間（「今年只剩…」「本月」）或綁月份的標題；頁首「更新」日期不比內文提到的時間舊
- [ ] 用詞照站內正式名表；沒有繁簡殘字、外文殘留、佔位字、`[[slug]]`
- [ ] 沒有 AI 殘留與 brief 外洩：`<context>` 這類標籤、「插入實例：」「本文規劃將回答」、寫作 brief 的受眾設定
- [ ] 用字與標點：回饋（不是反饋）、「」引號、FAQ 用全形「？」、同一篇的你／妳不混用

### 事實與產品
- [ ] 實體名稱、編號、結構張數對照事實表
- [ ] 每一句產品說法（功能、免費條件、價格、可用的工具）照真相順序核對過：先用無痕視窗、不登入實際走一遍流程，再對程式設定與價格頁；介紹頁不能當依據
- [ ] 沒有情境錯置：沒寫到產品沒有的服務型態（例：線上工具寫「預約時當面問」「切忌重複洗牌」）
- [ ] 參考資料可以驗證、跟主題相關；不是搜尋結果頁、消歧義頁或另一主題的條目；無法自動確認的已列 `decide`
- [ ] 求助資源只用白名單裡的（例：台灣 110、113、1925、165）

### SEO 欄位與結構化資料
- [ ] `<title>` 連同尾端品牌 ≤32 個全形字（英文約 60 字元），前 12 字是主要意圖詞；描述 50–80 個全形字（英文約 120–155 字元）
- [ ] 改標題時 9 處一致：`<title>`、og:title、twitter:title、JSON-LD headline、keywords、麵包屑最後一項、H1、封面 alt，以及頁首關鍵字列（這是內部欄位外洩，應從模板移除；移除前才需要同步）；新標題已登記標題帳本 `title-changes.csv`
- [ ] 標題層沒有假人設或保證字樣（title、H1、og、twitter、headline、描述都掃過「專家告訴你」「真實經驗」「一定」這類字）
- [ ] 描述 4 處一致：meta、og、twitter、BlogPosting
- [ ] FAQ（上線門檻）：結構化資料裡的每一題都逐字出現在畫面上，JSON 可解析；畫面上沒有的題目不在結構化資料裡
- [ ] FAQ（新寫與重寫）：畫面與 FAQPage 的題數、題目、答案、順序完全一致；既有模板差一題的已列 should_fix 交給產生器
- [ ] 沒有為了搜尋版面新增 FAQ 或 FAQPage（Google 自 2026-05-07 起已不顯示 FAQ 複合式結果）
- [ ] 隱藏欄位跟著內容改了：刪了畫面上的參考資料，就一起刪 JSON-LD 的 citation；拿掉的人名也從 about 拿掉；wordCount 與閱讀時間依新篇幅重算（中文約每分鐘 350 字）
- [ ] 作者是品牌組織，或有作者頁的真實具名作者；AI 角色不標 Person，沒有捏造作者
- [ ] AI 參與產出的 title、描述、結構化資料、圖片 alt 已人工查核
- [ ] 頁首沒有模板外洩：沒有「關鍵字：」這類內部欄位，日期是一般格式（不是 `2026-04-10T00:00:00+08:00`），閱讀時間、篇數由產生器依實際內容計算
- [ ] 網址、canonical、datePublished 沒被改；dateModified 只在實質修改時更新
- [ ] 結構化資料依 Google 規格驗證過（`node scripts/schema-validate.mjs --build-dir <建置目錄> --fail-on error`，再用 Rich Results Test 抽查）

### 頁面基本結構（細節見 `16`）
- [ ] 只有 1 個 H1，標題層級照順序（H1→H2→H3），主標題是文字，不是做在圖片上
- [ ] 網址在發布前定案：短、只留主題詞，不放年份（內容本身綁年份的除外）、流水號或亂碼片段；發布後要改就得做 301
- [ ] 圖片有寬高屬性，alt 描述圖片本身（可以自然帶到主題詞，但不堆詞），格式與大小照 `16`

### 連結與 CTA
- [ ] 內連 3–5 條，目標存在、不是轉址網址、不在排定 301 的清單上
- [ ] 同一目標只連一次；錨文字說清楚那頁講什麼
- [ ] CTA 去處在 CTA 路由表（`cta-map.md`）裡、指向站上存在的頁；實際點過一次，點下去就能開始（不是只回首頁）
- [ ] 文章教的方法和 CTA 打開的工具一致（張數、牌位、步驟），不一致時 CTA 前寫明工具用的是哪一種
- [ ] 按鈕旁一句話寫清免費條件與要不要登入；用無痕視窗、不登入走過一次，頁面上每一句承諾都和流程一致
- [ ] CTA 連同前後兩句讀過：不會讓人以為站上做得到其實做不到的事（張數、次數、免費範圍）；不塞整串標題；沒有讀者做不到的動作（例：「抽一張命運之輪」）
- [ ] 延伸閱讀的說明句描述的是目標頁「現在」的內容（目標改寫過就要更新）

### 手機與版面
- [ ] 390px 與 320px 寬：整頁 scrollWidth 等於視窗寬，沒有橫向溢出
- [ ] 每個表格外包 `overflow-x:auto`（`<table>` 數＝外層容器數）；5 欄以上或含長英數字串的表給最小寬度；首欄短標籤 `white-space:nowrap`，窄欄不會每行只剩幾個字
- [ ] 截圖：改前／改後整頁＋最寬表格；落地頁另拍 390×844 與 1280×800 第一屏與整頁
- [ ] 主要動作（提問框、按鈕）仍在手機第一屏
- [ ] 內容頁第一屏的提問框（如果有）是部署時就寫進 HTML、樣式內嵌，不靠 JS 事後插入：框頂在 390×844 的第一屏內（<844 px）、每頁恰好一個、CLS <0.01、輸入框有標籤；讀者的提問交給工具頁時不經過網址（做法見 `06` 第 3b 步；怎麼量與驗收見 `17`）

### 審查
- [ ] 跑過 `node scripts/content-audit.mjs`，沒有新的模板、堆砌、斷連結
- [ ] 由另一個代理用 `prompts/content-reviewer.md` 審過，must_fix 已清零
- [ ] 新文案全文已照回報格式（`07` 步驟 6）貼給使用者看過

## B. 整批

- [ ] 產文程式已先修好，或確定這批不會被它覆蓋
- [ ] 產生器風險清冊（`generators.md`）已更新；在暫存複本依序實跑清冊上會碰到這批檔的腳本，和修正版逐檔比對零變更；修不好的標「禁止執行」
- [ ] 沒有人在本機跑會整批重產頁面的腳本（主題刷新、樞紐頁重建）；所有重產腳本支援 `--check` 且跳過人工維護頁（`protected`、「手改，勿重產」）
- [ ] 部署前 SEO 差異檢查：可索引頁沒有新增 noindex、canonical 沒有改指別頁、受保護頁的正文沒變、dateModified 沒有倒退、FAQPage 的題目都在畫面上（`node scripts/seo-diff.mjs --before <上線版> --after <新建置>`；結束碼 2 表示有擋下項目）
- [ ] 同一頁的副本（無副檔名版、鏡像頁）逐位元一致
- [ ] 標題傳播照 `08` 決策規則 6：所有改過的標題都在標題帳本；三種碰撞（新標題包含舊標題、兩頁舊標題相同、舊標題藏在描述或 CTA 裡）都以 slug 定位欄位處理；舊標題連同變體（帶站名後綴、HTML 跳脫、截斷版）殘留為 0；替換腳本重跑零變更
- [ ] sitemap 通過 XML 驗證；JSON-LD 全部能解析；改過的檔改前改後標籤數與引號數相同
- [ ] 結構化資料與 sitemap 裡的資產網址（`logo`、`image`、`image:loc`、`og:image`）逐一打一次：200 且 `content-type` 是圖片（CDN 子網域也要查）
- [ ] 網址清單差異檢查：重產 sitemap、列表、llms-full 前後各存一份網址清單；被移除的網址都在本批的退役／合併清單上；正規化轉址（`.html`→無副檔名）的目的地沒被當成下架移除；新增的網址回 200、canonical 指向自己
- [ ] 列表頁、分類頁的描述已重建（不只標題），重建完成後才抽查驗收
- [ ] sitemap、llms 文件已更新；lastmod 依實質內容變動計算
- [ ] 在已同步副本的暫存複本跑過完整部署測試；本批碰到的受保護字串（前幾波測試鎖住的摘要、連結數、界線句）都還在，或測試已同步更新並寫明理由
- [ ] 剩餘問題清單（`leftovers.tsv`）：`danger` 與 `propagation` 的 open 是 0；其餘 open 項目已逐條寫進給使用者的報告
- [ ] 沒動到凍結期內不能動的頁（首頁、測試中的頁、正在觀察的試驗頁）
- [ ] 經正式部署流程上線（測試通過才部署）

## C. 合併／轉址波次（有轉址時才做）

- [ ] 主文已修好（`needs_main_fix=false`），被轉頁的段落已搬進主文；對照表這些列的 status 至少是 `moved`
- [ ] 主文標題／H2／FAQ 已寫進被轉頁在接的查詢詞
- [ ] 成員之間的定義（牌位、步驟、規格）已先統一，搬進來的段落也改成同一套
- [ ] 轉址前已列出舊頁前 20 個查詢，不屬於目標頁意圖的已寫進目標頁的排除清單（判讀時新舊合計）
- [ ] 轉址涵蓋無副檔名、`.html`、尾斜線，全部一跳到最終網址；沒有鏈狀
- [ ] 被轉頁已從 sitemap、llms 文件、列表、分類、樞紐清單移除（只移除目的地是別頁的轉址來源）
- [ ] 全站沒有連到被轉網址的內連（`crawl-site.mjs` 檢查）
- [ ] 正式站逐條 `curl -sI`：301＋正確 Location，目標 200；通過的列 status 改成 `verified`
- [ ] 本波條數合理（第一次先 10 條左右的試驗；之後一波再拆 2–3 批）
