# 提示詞：站內關鍵字→頁面稽核

**用途**：回答「{大字們} 為什麼沒有頁在接，或接得不好」。只看自己的頁面、內鏈、錨文字與技術面，不看競品。結果寫回 `.seo-agent/keyword-map.csv`，並排出可修改的檔案清單。

**何時用**：搶大字前；GSC 出現多頁互搶；排名卡在第 9–12 名；改版前要確認承接頁。

---

```
範圍：只看 {site} 自己的頁面、內鏈、錨文字與技術面，回答「{大字們} 為什麼沒有頁在接，或接得不好」。
只讀：不修改 repo、不 commit、不部署、不改 GSC／GA4 設定。

方法：
1. 正式站：用 Googlebot 手機版與一般瀏覽器各抓一次（語言設定含 {主語系} 與 en-US），比對 HTML 是否相同。
2. 原始碼：先確認版本。git fetch 後，把本機版本和「正式站目前部署的版本」對齊（看平台部署清單，或 CI 最後一次成功部署的 commit）；對不上，就把正式分支匯出到暫存目錄再掃（例如 git archive origin/main），並抽 3–5 頁和正式站比對。然後靜態掃描 sitemap 全部網址對應的檔案（或用 crawl-site.mjs 的結果）。
3. 瀏覽器渲染：用 Googlebot UA 渲染關鍵頁；擋掉所有分析與第三方請求，不要汙染 GA4。比對原始 HTML 和渲染後 DOM 的 title、H1、主要段落（前端多語字典可能在 JS 執行後把字換掉）。
4. GSC：同一檔裡的查詢×頁面，只用定稿資料。網址先正規化（.html、/index、尾斜線、大小寫合併；301 來源併進目標頁），再算互搶與承接比例。
5. URL Inspection：關鍵頁的索引狀態、Google 選的 canonical、最後檢索時間。

「可索引字數」的算法：拿 Googlebot 收到的原始 HTML，去掉 script、style、header、footer、nav、對話框和 hidden 區塊，再數非空白字元。

產出（繁體中文 Markdown）：
1. 工具／落地頁盤點表：title、description、H1、主要 H2、可索引字數、canonical、hreflang、JSON-LD、第一屏有沒有工具、進站連結（頁數／條數，並按位置拆開：頁首、頁尾、麵包屑、列表與分頁、相關區、CTA、內文）、主要錨文字（次數）、最後檢索日。
2. 關鍵字矩陣（每個大字一列）：曝光／點擊｜Google 目前給的頁@排名｜最適合承接頁｜承接頁本體有沒有這個字（title／H1／內文次數）｜其他 title 含這個字的頁（含列表頁與分頁）｜含這個字的錨文字總數→指向承接頁的條數｜標記（互搶／錨文字 0／本體缺／沒有頁／錨文字分裂／列表分頁搶字／修飾詞只在別頁）。
3. 各版型的固定連結表（頁首／頁尾／麵包屑／CTA），以及「文章、實體頁連到各工具頁」的來源頁數；CTA 連到首頁或泛用頁的文章占多少。
4. 技術面：爬蟲拿到的語言、SPA 與重複網址、sitemap／robots／canonical／hreflang、原始 HTML 裡有沒有文字、哪些頁靠 JS 才有內容。
5. 最可能的原因：依「受影響字的曝光量＋證據直接程度」排序，每項附可修改的檔案與行號。同時列出所有會蓋回修正的地方：生成器或批次腳本、前端多語字典、產生器裡的常數、獨立的結構化資料檔、會強制改值的後處理腳本、鎖住舊字串的測試。
6. 限制：曝光不等於搜尋量；渲染工具不等於 Google 的渲染；掃的是哪個版本；哪些數字沒有重新驗證。

最後附 400 字以內的摘要。
```

## 使用注意

- 「兩頁都有曝光」不等於互搶；要看主網址輪替，加上全站成效變差（`references/04` 第 8 步）。同一頁的 `.html` 與無副檔名版本同時拿曝光，是技術問題，不是內容互搶。
- 「文字沒有完全一致」不等於 Google 不理解。補同義詞值得做，但不要把每個缺字的位置都列成重大缺陷。
- 帶參數的功能入口（例：直接開啟某個工具模式）不一定是錯的；只有「了解、比較」類的連結才要指向 SEO 承接頁。
- 入鏈總數會騙人：頁尾和列表分頁撐出來的數字很大，內文連入可能是 0；承接頁很久沒被重新檢索，通常代表訊號弱。
- 案例用這份稽核找出：
  - 大字錨文字幾乎全連到文章（489 條，連到承接頁 0 條）。
  - 同一錨文字分裂（889 條連首頁、810 條連別頁）。
  - 811 篇文章連到 6 個工具頁的連結全是 0。
  - 35／36 張子市場實體頁是孤兒。
  - 知識總覽頁 1,027 條連入有 810 條在頁尾，內文連入是 0；部落格列表與 16 個分頁的 title 都含最大的字。
  - 首頁文案分散在 5 個寫入點，其中前端多語字典沒改，渲染後會換回舊字。
- 案例曾在本機落後正式版 125 個 commit 時掃原始碼，內鏈統計整份作廢；另一次差點把已上線的長文誤報成「還沒上線」。所以方法第 2 點的版本確認不能省。
