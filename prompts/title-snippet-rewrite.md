# 提示詞：title／description 改寫（有證據、可核對）

**用途**：改寫一個頁群的 title 與 description，每一句都要能在頁面上找到出處，而且對準使用者實際搜的寫法。規則見 `references/09-ctr-titles-snippets.md`。

**何時用**：`gsc-opportunities.mjs` 列出 CTR 缺口或有曝光 0 點擊的頁之後；一次只用在一個頁群。

---

```
任務：改寫 {page_group} 中 {N} 個頁面的 title 與 meta description。
這一波的型態：{摘要實驗／贏家擴大}（定義見 references/09 第 6 步）。

輸入：
- 每頁的 90 天與 28 天數據：曝光、點擊、CTR、排名。
- 每頁的主要查詢詞（曝光／點擊@排名），來自 GSC 查詢×頁面（同一檔），並標出每個查詢的類型：自家意圖／他站品牌或導航／無關長查詢。
- 每頁的全文、FAQ，以及頁面上標示的結論或傾向（例：是否題偏是或偏否）。
- Google 目前實際顯示的標題與摘要（人工截圖；沒有就寫「未看」）。
- 觀察中的頁面清單（上一波還在量測，不能動）：{watch_list}
- 品牌寫法：{brand_suffix}。長度照 references/09 第 3 步：title 含品牌 ≤32 全形字、品牌在尾端（英文約 ≤60 字元）；description 50–80 全形字（英文約 120–155 字元）。中日韓字算 1，半形英數與空格算 0.5。

規則：
1. 觀察中的頁跳過並說明原因，依曝光往下遞補。
2. 他站品牌、導航字、無關長查詢占某頁曝光一半以上時，這頁不列入，說明原因。
3. title 開頭放使用者實際搜的寫法：別名、俗稱、編號（例：「{實體}（{別名}）」「{子分類}{實體}（{編號}）」）。
4. 長度照上面的規範；實體頁的前 12 字要有意圖詞（意思、變體名、情境）。
5. 可以用頁面已經回答的疑問句當鉤子（例：「{實體}{變體A}／{變體B}意思：{常見疑問}？」）。
6. description 用「答案先行」：先給兩個主要變體的答案，再說本頁整理了哪些面向。
7. description 的每一句都要能在頁面原有段落或 FAQ 找到；寫「偏是／偏否」要和頁面標示一致；不承諾頁面沒有的內容。
8. 不寫釣魚標題（「揭開…的神秘面紗」）；只有部分免費時不寫「免費線上○○」；不放他站品牌；不刻意塞錯字。
9. 不要和站內其他頁搶同一個查詢：如果某個問句已經由另一篇文章承接，就不要把它放進這頁的 title。
10. 不要所有頁都套同一個後綴（例：「｜完整解析與重點整理」）；每頁都從它自己的主要查詢寫出具體答案。
11. 摘要實驗只改 title、description（og、twitter、JSON-LD description 同一句）、答案式開頭或 TL;DR、修改日期；正文、H1、CTA、內鏈不動。
12. 發現頁面內容本身有錯（例如和其他頁矛盾的 FAQ）時，另列出來，不要自己改內文，除非任務允許。

輸出：
1. 表格：頁面｜舊 title｜新 title｜新 description｜對應的主要查詢（曝光／點擊@排名）｜相關查詢（判定只用這組字）｜每句描述對應的頁內段落。
2. 刻意不動的頁與原因（觀察中、查詢組成不合格、排名 >8 問題在排名）。
3. 發現的內容錯誤或矛盾（附位置）。
4. 驗收計畫：D+7 看風險與方向、不下結論；D+14 期中；D+28 正式（窗口照 references/09 第 7 步：排除部署日涵蓋的 PT 日後前後各 28 天）。對照組是同型、這次沒改的頁。判讀前先看 Google 實際顯示的標題；被改寫的頁另外標註。
```

---

## 使用注意

- 改完先給使用者審稿，再上線。摘要實驗一次改齊 title、description、og／twitter、JSON-LD headline／description；贏家擴大才連 H1、開頭、CTA、延伸連結一起改，報告只能寫「整體方案效果」。日期用這一波固定的修改日。
- 上線時把每頁的「相關查詢」寫進 `templates/wave-record.md`；事後才挑哪些字算數，等於挑對自己有利的結果。
- 判讀時拆到查詢層級：點擊掉了，先看是不是丟掉離題字（案例 8 頁 −31%，主因是離題字曝光歸零）。
- 案例用這份規則改了 15 張實體頁，D+7 的結果（只看方向）要兩個版本並列：用原訂前窗，處理組 −10%、對照組 −11%（幾乎沒差）；換成扣掉爆量的前窗，是 +10% 對 −28%。每日只有約 3 次點擊，CTR 0.74%→0.58%，原報告判「信心：低」、待 D+28。不能寫成「對照組證明有效」。
- 驗收判定有效的標題，寫進回歸測試鎖住（`references/09` 第 7 步），免得被產生器或 AI 重寫蓋掉。
