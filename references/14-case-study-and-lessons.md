# 14 · 案例與教訓：一個繁中塔羅占卜工具站的半年實錄

> 這個 skill 的每條規則都有來由，來由就在這一章。
> 案例站是一個繁中塔羅占卜工具站。2026 年 3 月上線，之後半年經歷了：大量自動產文、Google 核心更新、十多波站內改動、一次外部爆量、一次首頁搶大字成功又被收回、一次核心字護欄觸發，以及全站逐篇審稿。
> 結論只有一句：大起大落幾乎都來自 Google 與外部需求。站內效果最明確的只有三類（證據強度各不同，見步驟 3）：
> - **讓 Google 讀得對**：爬蟲語言修正（機制＋時間）。
> - **讓主題集中**：hub 補齊連結，同意圖的頁整併（前後比、期中；hub 補連結是 D+7 的方向，待 D+28）。
> - **讓進站的人開始用**：在第一屏放提問框（三期比較，顯著；做法見 `17`）。
>
> 量測紀律的價值，是不把運氣記成功勞，也不因外部波動盲目回滾。

## 何時使用

- 要跟使用者解釋「為什麼要這樣做」：例如為什麼要等 D+28、為什麼不能整批回滾、為什麼不再批量產文。
- 接手新網站的第一個月，想先避開別人踩過的坑。
- 遇到相似情境時（流量暴漲、大字掉了、文章太多、要不要整併、要不要搶首頁大字、流量有了但沒人用），查當時發生什麼、怎麼判斷、結果如何。
- 要替你的網站寫案例紀錄時，參考本章格式。

## 步驟

### 步驟 1：先看案例站的條件

拿案例對照你的網站前，先比較規模與權威。

| 項目 | 案例站 |

| 內容 | 約 820 篇文章（清理前有 1,654 個檔案：每篇都有「無副檔名＋.html」兩份）；另有 78＋36 張牌義頁 |

### 步驟 2：找相似情境（時間線）

證據強度的意思：
- **對照組**：有未改頁或安慰劑校正，可以當成可複製的做法。
- **顯著**：產品端的比率差異有檢定支持（Fisher、z 檢定），入口人數達門檻。
- **前後比**、**期中**、**長期趨勢**：只是方向，要在你的網站重新驗證。
- **機制＋時間**：作用機制清楚，時間也對得上（例如修好之前 0 曝光、修好之後才有）。
- **外部**：不是我們做的。
- **方法**：流程或量測上的做法。

| GEO | 生成提示要求「堆具名實體、附權威參考」 | 285 篇堆了同一組人名；參考資料與主題無關，或根本無法驗證 |

### 步驟 4：引用給使用者時

- 用相對數字（例如「曝光 3.8 倍」），並說明證據強度。「前後比」不能說成「已證實」。
- 只有證據強度是「對照組」或「顯著」的做法，才當作可複製的建議；其他的當假說，在對方網站設對照組重新驗證。
- 轉換類的結果（提問框、CTA 深連結、登入時機）是產品指標，不能說成排名的功勞；引用時照 `17` 的口徑（只算自然搜尋 session、按入口類型）。
- 案例早期（上線頭兩個月）的曝光類數字落在 GSC 曝光記錄錯誤期，引用時只用點擊。
- 例（非占卜站）：
  - 咖啡器材站問「要不要像案例那樣整併同主題文章」。
  - 你的回答：案例 11 篇整併成 2 頁後曝光 +55%（期中、無對照）。建議先拿「手沖濾杯推薦」這一組 6 篇試，設對照組，D+28 再決定第二批。

| 新站搶大字守不住 | 先確認權威差距；搶大字的同時做站外；不要對大字承諾名次區間 | `04`、`06`、`12` |

**如果重來一次：新網站的順序**

1. **量測與技術地基先行**：事件語意、GA4 時區、參數不撞 GA4 內建名稱、後端購買事件逐筆對帳、GSC 與 GA4 的 BigQuery 匯出第一天就開；爬蟲看到的語言、canonical、robots 群組、lastmod、轉址一跳到位。每條規則都要有部署前、部署後兩道檢查。
2. **建 D0 基準，從第一波就設對照組**：不要等到第三波才發現前後比不可靠。
3. **一個字族一個網址**：首頁和工具頁先分工；子市場（中型字）用 hub 加內鏈先拿。
4. **不批量產文**：先建品質閘門，題目必須有 GSC 查詢證據，而且站上還沒有同題頁。
5. **站外第一天就開始**：外部連結網域只有 2 個的站，守不住大字的前 10 名。
6. **每一波都照規矩來**：預先登記、記 D0、設護欄、D+7／14／28 驗收；重大判斷交給兩個獨立模型交叉審查。
7. **落地頁第一天就有入口**：文章、hub 的第一屏就放提問入口，CTA 直接開到對應的工具流程；驗收只看自然搜尋 session（`17`）。

| 早期說法 | 修正後 | 怎麼抓到的 |
|---|---|---|
| 第一波改過的頁點擊 +46～58% | 改版前兩週就已經比對照組多漲六成；DiD（扣掉異常後）−1.1% | 安慰劑 |
| 第二波的摘要整波有效 | 4 頁摘要清洗後 +7.7%（p=0.65），乾淨 5 天 −0.9%；早期的增量多來自他站導航字 | 查詢清洗＋DiD＋截斷乾淨版 |
| 第二波的 CTA 深連結無效 | 它是轉換改動，GSC 量不到；自然搜尋拿到完整結果的 session +61%（前後比） | 改用自然搜尋 session 的口徑 |
| 「曝光 +45%」是成長 | 8→9 月的曝光增量裡有 34.5% 是無效曝光（「+45%」是滾動 28 日窗，和 34.5% 的分母不同） | 分頁群清洗 |
| 首頁流量被工具頁搶走 | 首頁從來沒有一般字流量；兩頁內文相似度只有 0.012–0.017，衝突只在 title＋H1 | 互搶勝場、內文相似度 |
| 某篇文章「流失」到 0 點擊 | 基準期本身是 7 天的外部事件，主查詢其實是他站網站名 | 逐日資料、查詢意圖 |
| 新 title 造成退步 | Google 看到新 title 之前，名次就已經在掉 | 最後檢索時間 |
| 期中全站 +22.7% | 避開爆量日只剩 +4.7%，判持平 | 多版本並列 |
| 大字「掉回改定位前的 15–19 名」 | 改定位前本來就是 0 曝光 | 查改動前的歷史 |
| 站內修好後，大字會從 9–12 名推進到 5–8 名 | 方案寫好的三天前，一般字已經整群重排，之後 −96%；不要對大字承諾名次區間 | 定稿數字 |
| 某個轉換改動是第二原因 | 刪除：只差 3–4 個 session（p=0.12），安慰劑落在雜訊內，宣稱的比率也無法重現 | 滾動窗安慰劑＋重現 |
| 「Google 那天才重抓，所以能排除其他改動」 | 最後檢索只是最近一次；只靠時間，只能排除較晚上線的改動 | 機制審查 |
| D+14 仍為 0，就定案「只有第二頁實力」 | 不定案；title 類改動要到 D+28 才判 | 雙模型裁決 |
| 外部引用要等驗收完再做／站外動作不會汙染站內試驗 | 立刻開始（外聯不改網站）；但新上線的引用可能帶動品牌搜尋與排名，每一筆都記成外部事件，驗收時列為干擾 | 雙模型裁決 |
| 首頁 GA4 只記到 GSC 點擊的 42–73%，是 gtag 延後載入造成的 | 延後載入前後，全站兩個比值都沒有下降（0.317→0.359、1.065→1.078）；42–73% 是首頁單頁的水準比值（點擊不等於 session） | 前後比值對照 |
| 付款事件只漏收 5 天 | 伺服器購買事件約 19 天一筆都沒進 GA4 | 逐筆對帳 |

## 對應腳本（哪支腳本防住哪個坑）

| 案例中的坑 | 本 skill 怎麼防 |
