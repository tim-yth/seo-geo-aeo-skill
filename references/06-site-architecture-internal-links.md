# 06 · 網站架構與內部連結：hub／pillar／cluster、工具優先、第一屏入口、CTA 路由、錨文字、變體整併、生成器陷阱

## 何時使用

- 新站規劃，或要新增一組頁（工具頁、子市場 hub、實體頁）。主題範圍怎麼畫見 `04` 第 6b 步。
- 稽核發現孤兒頁、hub 排不上、錨文字錯配，或工具頁幾乎沒有入鏈。
- 搜尋進來的人沒有開始使用：要改落地頁第一屏、提問框、範例問題、CTA 去處（怎麼量、怎麼驗收見 `17`）。
- 同一主題有多個變體頁互搶（「完整指南／新手避坑／常見誤區／實戰教學」這類同題換字尾）。
- 要改共用模板、導覽選單、產文或批次刷新程式之前。

本文的 ○○ 代表主題詞；「案例」指案例站（繁中塔羅占卜工具站）。

原則：連結的目的是讓讀者知道下一步去哪裡，不是堆出幾千條連結。中型字吃結構，大字吃權威（見 `04` 第 9 步）。

## 步驟

### 1. 盤點：頁型、連結圖、錨文字

用 `node scripts/crawl-site.mjs` 全站爬一次，至少看這些：

- 每頁的進站連結（頁數與條數）、出站連結。
- **入鏈要按位置拆開算**：頁首、頁尾、麵包屑、列表與分頁、相關區、CTA、內文。頁首頁尾和列表分頁的連結再多，也不代表有主題相關的內文連入。`crawl-site` 的 `-text.jsonl` 裡，每頁的 `links` 只收 nav、header、footer、aside 以外的站內連結，可以先算「非框架入鏈」；麵包屑、列表分頁、相關區、CTA 和內文要再看 HTML 區塊細分，或用 `internal-links.mjs`（第 5 步）。
- 每個錨文字指向哪裡；同一個錨文字是不是指向不同頁。
- 孤兒頁：不在任何索引頁、而且入鏈為 0。
- hub 到子頁的連結是寫在原始 HTML，還是要靠 JS 或 `#hash` 才出現。
- 麵包屑（可見的與 JSON-LD）指向哪一層。
- 功能路由（SPA、帶參數入口）吃了多少站內連結。
- **點擊深度**：用 `crawl-site --no-sitemap` 從首頁只靠連結爬一次，`depth` 欄才是離首頁幾次點擊（從 sitemap 加進來的網址沒有深度）。重要承接頁比同類頁深很多時，檢查 hub 和選單有沒有直接連它。
- **承接頁很久沒被重新檢索，是訊號弱的徵兆。** 用 `indexing.mjs inspect` 看最後檢索日。案例的知識總覽一個月沒被重抓，名次 @29；同期首頁和工具頁大多在一週內就被重抓。先補內文連入和內容，再考慮請使用者手動要求建立索引（`10` 的 8.3）。

案例稽核時的實況：
- 811 篇文章、114 張實體頁連到 6 個工具頁的連結全是 0。
- 知識總覽頁有 938 頁、1,027 條連入，看起來很多；拆開後 810 條是全站頁尾，內文連入是 0。指向首頁的 3,723 條連結裡，內文只有 81 條。
- 另一個工具頁的 44 個來源頁裡，17 個是部落格列表和分頁，沒有任何一篇文章。
- AI 工具頁只有 40 頁連入；另一個工具頁只有 6 頁連入。
- 子市場的 36 張實體頁有 35 張沒有任何站內連入。
- 抽牌功能路由和首頁同一份 HTML，卻吃了 1,503 條站內連結。

### 2. 套用 hub／pillar／cluster 模型

先用主題地圖（`04` 第 6b 步）決定有哪些主題與子主題、每個由哪一頁接，再套下面的頁型與連結方向。

| 頁型 | 負責什麼 | 連結方向 |
|---|---|---|
| 工具頁（行動意圖） | 一個意圖一頁（AI、是否、愛情、每日、子市場…），第一屏就能用 | 工具頁彼此全連；連到相關知識頁 |
| 知識 hub | 一個主題的總覽與完整目錄（例：78 張牌義總覽、子市場 36 張目錄） | hub→每個子頁；子頁→hub |
| cluster 頁 | 單一實體或單一問題（單張牌義、單一知識文） | 子頁→hub、子頁→相關子頁 |
| 導讀 pillar 文章 | 入門、牌陣、愛情、線上占卜指南 | 只收內鏈，**不收轉址** |

- hub 要少量精選＋明確分群＋可控分頁。案例的文章總覽一頁列出數百篇（約 1MB），手機變慢，權重也被稀釋。
- **非塔羅示意例（電商）**：分類 hub「女生跑鞋」→商品頁；選購指南 pillar「跑鞋怎麼挑」→分類與商品；商品頁麵包屑回分類 hub，不回「全部商品」。
- **非塔羅示意例（SaaS）**：功能 hub `/features/`→各功能頁；情境頁「行銷團隊怎麼用」連到相關功能頁與定價頁。

### 3. 工具優先：第一屏就能用

工具頁的固定結構：

1. H1 直接命中主字；同義字放進 title 或副標。
2. 一句話的快速答案（長度照 `09` 第 3.1 步的 TL;DR），讓 AI 可以直接引用。
3. **第一屏就是工具**：第一個輸入框前的說明壓在約 100 字內，附 3–4 個範例問題按鈕。案例的競品是 66–144 字；案例站原本首頁 94 字、AI 工具頁 207 字、是非工具頁 234 字。
   - **範例問題一點就送出**，不要只填進輸入框：讀者幾乎不打字。送出走表單本身的流程，事件和手打的一樣。案例落地頁 28 天約 8,100–8,300 人（依清洗口徑），只有約四分之一開始使用，之後把範例改成一點即送出。
   - **每頁自己的題目**：用頁面層的宣告（例如一個 meta 欄位）列 3–4 題，依該頁主題寫成讀者會說出口的話。先做自然流量前 20 名的頁，再擴；沒宣告的頁只顯示一般提問框。用測試鎖住清單：哪些頁有範例、每頁幾題、雙胞胎檔一致。
   - **入口頁（hub）的 hero 就是表單**：直接收問題，表單帶工具模式參數（哪一種工具或組合），送出就進對應流程。表單旁放「直接開始（不用打字）」，加 3 題一點即送出的範例；hero 只留一句定位，其餘說明移到表單下方（仍在原始 HTML 裡）；問題要等後面步驟才用到時，先存起來，那一步出現再填入。案例的子市場 hub，以及 AI、是非等入口頁都照這樣改。
   - 例：SaaS 計算機頁的範例「月營收 50 萬、3 人團隊」，一點就算出結果；電商「跑鞋怎麼挑」hub 的 hero 放「說說你的跑量和腳型」＋「直接看推薦（不用填）」，送出帶 `?category=running`。
4. **免費條件一句話寫清楚**，而且要和程式、價格頁一致（例：「免註冊可先看前半段；首次註冊送一次完整結果」）。不要寫「完全免費」。
   - **條件寫在輸入框或主按鈕旁**，不能只放在 FAQ。這類修正只改文案、風險低，但改的是受保護頁時，仍要單獨一批、記 D0。
   - **用無痕視窗、沒登入，把落地頁的每一句承諾和實際流程逐句對**：張數、步驟、看得到多少、要不要登入、空白能不能送出、之後要付什麼。
     - 案例的是非工具頁寫「抽一張牌」，按鈕卻進通用流程；那段期間這頁自然落地輸入率 76%→44%。
     - 案例的 AI 工具頁同時有三處對不上（張數、要先登入、空白不能送出），可見文字裡「登入、註冊、預覽、開頭」都是 0 次，完整條件只寫在下方 FAQ。
     - 子市場落地頁寫三張、工具抽五張；淺色落地頁一按就跳到深色工具頁；選了範例題還要再按一次開始。這些都會掉人。
   - **登入放在看到價值之後**：先讓人看到結果開頭，在「展開完整結果」時才要求登入。案例這樣改後，登入完成率 74%→90%（差異顯著，但同一天也改了鎖卡版面，歸因是推測）。多加一種第三方登入，前 5 天只看到它分走既有方式的解鎖（11 人，待觀察）；不要預期它會多出使用者。
   - 例（電商）：分類頁按鈕寫「免運直接買」，實際未滿額要運費、而且要先登入；改成按鈕旁寫「滿 990 免運；可用訪客結帳」，並確認流程真的支援訪客結帳。
5. 適合做什麼、不適合做什麼。
6. 怎麼運作（3–5 步）。
7. **可被爬取的範例結果**（150–250 字），標明是示範、怎麼產生的。手寫的範例等於另一種假見證，所以範例要可稽核：
   1. 用正式的流程產生：同一段抽樣或計算程式、同一份提示詞與參數，實際跑一次；第一則就採用，不挑結果。
   2. 保存原始紀錄：產生時間、輸入（問題、抽到的項目、亂數或種子）、參數、完整原文。頁面上的摘錄只從原文裁切，不加字。
   3. 和正式服務有任何差異（模型、參數、長度上限），列成一張表交給使用者決定要不要揭露；有差異時，頁面寫「示範，非即時結果」。
   4. 範例裡的題目要是工具真的答得出來的（例：三張不分位置的牌，就不要示範「哪個月份會發生」）。
   - 例（SaaS）：「範本產生器」的示範輸出，用正式 API 與預設參數跑一次，存下輸入與完整輸出；頁面摘錄不手改。
8. **FAQ**：結構化資料裡的每一題都要逐字出現在畫面上（上線門檻）；新寫或重寫的頁，題數也要一致（`07`）。
9. 內鏈：相關知識頁、相關工具、價格、隱私。
10. **Schema**：WebApplication 或 Service＋BreadcrumbList；FAQPage 選用。Google 2026-05-07 起對所有網站停止顯示 FAQ 複合式結果（`15` 第 15 節）；要放就和畫面一致。

已經寫在原始 HTML 裡的收合內容，Google 仍讀得到，不必為了 SEO 全部展開。做法是工具下方展開約 120–200 字核心介紹，長範例和 FAQ 繼續收合，以免拉低手機開始率。動到第一屏、文案、收合區或按鈕時，照 `03` 步驟 3 再加一條產品護欄：該頁自然落地 session 的開始率不得下降。

案例：愛情頁原本是內容彙整頁，沒有工具，按鈕寫「返回首頁開始」；改成第一屏可提問的工具頁後，排名 16.5→10.9、曝光 ×5.5，點擊仍很少（D+7、樣本小）。

**要不要讓第一次免登入就看完整結果：當產品試驗做，不當 SEO 必做**
- 競品第一屏寫「免費・免註冊・30 秒出結果」，清單文和媒體也都提這點。但這只能支持「體驗和推薦意願」，不能保證名次；Google 也不會拿你 GA4 的跳出率來排名。
- **先查成本假設**：案例的後端其實已經先生成完整內容、再回傳截短的預覽，所以免登入展示全文，不一定多一次生成成本。真正的成本來自更多人開始、重複試用、追問和濫用。
- **試驗設計**：同期對照，只改「第一次要登入的時點」，不額外加碼；訪客的免費一次要和註冊後的首次免費接起來，不能變成兩次。給一次額度、設成本上限，而且不要和其他價格或付費牆試驗同時改。
- **驗收看什麼**：以「合資格的新訪客」為分母，看完成有效體驗的比例、七日再使用、付費人數、扣掉生成成本後的貢獻。收入集中在少數買家時，另列「不含最大買家」的版本。
  - 「完整內容被看的次數」增加，是規則改了的直接結果，不能單獨算成功；註冊率下降也不一定是失敗，要看後續價值。
  - 付費樣本不足時，結論維持「未定論」。
- **讀既有漏斗要注意分母**：案例「預覽 1,962 → 點解鎖 887 → 解鎖 577」是使用者數，大量流失發生在點解鎖之前，不能全算成登入的問題。「註冊後七日付費約 1%」的分母是成熟的註冊者，不能直接當成新訪客的付費率。

**非塔羅示意例**：電商分類頁第一屏放「尺寸／腳型選鞋器」；SaaS 功能頁第一屏放可直接試算的計算器，而不是一大段介紹。

### 3b. 內容頁與入口頁的第一屏入口（搜尋落地轉換的頁面做法）

文章、實體頁（詞條、商品說明）、hub 是搜尋流量最大的入口，讀者多半是來查資料的。這一步讓需要的人不用讀完就找得到開始的地方。為什麼要做、怎麼量（只算自然搜尋 session、同一 session、按入口類型分開）、怎麼驗收，見 `17` 與 `02` 步驟 3 第 14 點；這裡只寫頁面上怎麼做。這類改動屬於轉換，不是排名，照樣登記成一波、記 D0（`03` 步驟 1）。

**1. 第一屏提問框**
- **位置**：手機 390×844 的第一屏內；文章放在封面圖之前，詞條放在關鍵詞之後。一頁只放一個，文末不放第二個。
- **做法**：部署步驟直接把框寫進 HTML、樣式內嵌，不要等 JS 載入後再插。案例第一版為了不推擠畫面，用 JS 插在開場段落之後，結果落在 2,300–6,700 px，幾乎沒人看到。改成部署時寫入、放進第一屏（同批還加了手機底部列與範例題）後，內容頁輸入率 6.7%→14.6%。
- **提示語對應該頁情境**；實體頁可以用「就這一張問一題」，並自動帶入實體。
- **文案與樣式只有一份**：放在元件檔，部署步驟讀它寫入。
- **空框也能送出**：沒輸入就和頁面原本的 CTA 一樣，直接打開工具。
- **範例題**照第 3 步第 3 點：一點就送出。
- **瀏覽器測試**：框頂 <844 px、寬度等於閱讀欄、沒有橫向捲動、CLS <0.01、每頁恰好一個、輸入框有標籤。
- **量測**：開始事件只帶 `placement`（開場框／入口頁 hero／底部列）這類列舉值，用來比較入口；不帶提問文字。

**2. 提問交棒不經過網址**
- **交棒方式**：內容頁把提問存進同一分頁的 `sessionStorage`（單次、約 10 分鐘有效）。工具頁讀一次就刪除，預填並聚焦輸入框，但不自動開始；重新整理不再回填。
- **永遠不放進網址**：提問常含感情、健康、工作細節，放進網址就會進入分析的 `page_location`、伺服器與 CDN 日誌、Referer。表單用 GET 跳到工具頁時，輸入框不給 `name`，JS 失效也只會帶著工具參數過去。
- **多步驟工具**：輸入框在後面步驟才出現（例如先抽牌才問），就等它出現再填入。
- **瀏覽器測試**：拿一句測試提問與它的 URL 編碼版，確認網址列、全部網路請求、分析資料（dataLayer）三處都找不到。

**3. 手機底部開始列**（只在手機）
- 開場提問框還在畫面上時不出現，捲過它才出現；捲到文章自己的結尾 CTA 時讓開，不要兩個入口同時出現。
- 內容：有範例的頁顯示第一題（「問這題：…」）＋「直接開始」；沒有範例的頁只顯示「直接開始」。
- 點擊照樣走交棒（不經網址）；事件的 `placement` 記成底部列，和開場框分開比較。
- 測試：一頁恰好一條；開場框可見時隱藏；捲過後出現；到結尾 CTA 時隱藏。

**例**：
- SaaS 教學文件：每篇教學第一屏放「用你的資料試一次」，不要只放在文末。
- 電商：商品頁的「問尺寸」框交給客服視窗，同樣用 sessionStorage，不要把「我腳寬 10 公分」放進 `?q=`。

### 4. hub 連到每個子頁，子頁麵包屑回 hub

- **hub 端**：在原始 HTML 裡輸出全部子頁的目錄（編號、名稱、別名、2–3 個關鍵字），用標記區塊包起來，重跑時只替換這一塊。
- **子頁端，三處都指向正式 hub**：可見麵包屑、「返回總覽」連結、BreadcrumbList。
- **子頁正文**：在第一個正文段落（跳過摘要框、提示框、CTA、FAQ）放一條連到 hub 的連結，依序判斷：
  1. 已有 hub 連結、錨文字正確→保留。
  2. 錨文字不對→只改第一條，不新增。
  3. 段落裡已有這個片語→直接包成連結。要避開「{主字}師」這類較長的詞，也要跳過已在連結裡的片語。
  4. 都沒有→在段落末尾加一句模板句，多句輪替。
  - 按鈕不算正文連結。
- **驗收**：每頁恰好 1 條正文 hub 連結，位置在第二個標題之前；錨文字只用 2 種（hub 主字和它的線上變體），各占 ≥30% 頁面；子頁數量正確、編號不重不漏。
- **案例**：子市場 36 張實體頁的上層原本是「學院頁 `#子市場` 分頁」。Googlebot 不帶 `#`，渲染出來是另一個分頁，0 條子市場連結，結果 35／36 張沒有入鏈。hub 補上 36 條連結、麵包屑改指 hub；約一天後的另一次部署，在 hub title 加上「免費」。之後子市場主字每日曝光 ×3.8、排名 8.4→6.9、hub 點擊 ×2.5（D+7，只看方向）。兩次部署落在同一個觀察窗，只能寫整體方案效果；起漲日對上的是改 title 那一批。
- **非塔羅示意例（電商）**：品牌頁列出該品牌所有系列；每個系列頁的麵包屑是「首頁 › 品牌 › 系列」，不是「首頁 › 搜尋結果」。

### 5. 錨文字與內鏈規則

本節管架構層的方向、比例與數量；每一條連結本身怎麼寫（錨文字寫法、按鈕與文字連結的分工），見 `16` 第 5 節。

- **兩種連結分開處理**：
  - 「了解、比較、查資料」連到 SEO 承接頁。
  - 「帶著問題開始使用」保留功能入口（帶參數）。案例實測，把文章按鈕改成先經過 hub，會多一次頁面載入：手機從按鈕到送出 2.96→3.47 秒，所以功能入口不改。
- **錨文字要符合目的地**。案例修正：
  - 810 條「○○占卜」其實連到知識總覽，改成「○○牌義大全」。
  - 79 條「立即體驗 AI ○○占卜」其實連到首頁，改成「開始○○占卜」。
- **改錨文字也會間接碰到受保護頁。** 上面那 79 條模板按鈕改完，全站提到護欄字的頁從約 130 頁降到 51 頁，同一批還改了 1,509 條文章按鈕的目的地；上線隔天護欄字開始下滑。事後調查無法排除它，只能列為低信心候選。改全站錨文字或模板按鈕，照 `03` 算受保護頁的改動：單獨一批、記 D0、看護欄、遵守凍結。
- **錨文字多樣化檢查**（只用在情境連結）：36 條裡約 9 條核心詞、約 20 條帶語境的描述、約 7 條品牌或操作語句。這沒有官方比例。固定選單和麵包屑用一致的名稱即可；不要為了湊比例改壞自然的句子。
- **情境連結第一輪**：挑 12–36 篇主題相符、已有自然流量、缺工具出口的文章，每篇 1 條，接在原本相關的句子後面。避開會被批次模板重寫的文章（案例：一篇排名很好的文章在模板清單裡，重跑會整篇重寫，連新加的段落一起消失）。文章在接工具意圖的查詢時，工具連結放在第一段（`04` 第 7 步規則 8）。
- **相關項目區塊**（實體頁之間）：
  - 每頁 4–7 個。
  - 有順序的實體：前後各一個，再加 2–3 個主題相近的。
  - 有分組的實體：同組前後各一個、其他組的同號，可再加一個主題相近的。
  - 標籤寫「上一張／下一張／同類／主題相近」；每個實體至少被 3 頁連到；底部連回總覽。
- **文章內鏈下限**：每篇出站 ≥3、入站 ≥2。
- **補連結的建議怎麼排**（案例做法）：依「共同詞×2＋同分類 2＋入鏈缺口＋出鏈缺口」排序，每篇最多 3 條，全站先做前 30 條。
- **進階排序**（公開工具的做法，非案例實測）：
  1. 在連結圖上算內部 PageRank（阻尼 0.85、忽略 nofollow；出現在一半以上頁面的模板連結降權），加上第 1 步的點擊深度。
  2. 入鏈分成「正文裡的上下文連結」和「選單、頁首、頁尾的框架連結」；上下文入鏈 ≤1 的承接頁先補。
  3. 對每個承接頁，找正文已經提到它的主字或同義詞、還沒連過去、而且屬於同一個 hub 或相關主題的來源頁；跳過標題、既有連結、程式碼區塊裡的出現位置。
  4. 分數＝承接頁的機會（排名 5–20、有曝光的查詢）×來源頁的內部 PageRank×主題相符。
  5. 錨文字從 `keyword-map.csv` 的 `synonyms` 欄（同義寫法）輪替；同一組來源→目標只建議 1 條；不連到 noindex、非 200、非 canonical 的頁；放在第一個相關段落。
  - `node scripts/internal-links.mjs` 會產生這張建議表（讀最新一次 `crawl-site` 的 `-links.jsonl`、`-text.jsonl`；加 `--gsc <query×page 匯出>` 依機會排序）。建議永遠不自動套用，逐條審過才上；被補連結的承接頁就是 `gsc-compare` 的處理組。

### 5b. CTA 路由表：依序比對，點下去要真的能開始

全站只用一份路由表（建議存成 `.seo-agent/data/content/cta-map.md`），產文程式、修正代理、審稿都照它。`07` 與 `templates/fix-rules.md` 提到的「站內 CTA 路由表」就是這一張。

| 順序 | 文章命中 | CTA 去處 | 按鈕寫法 |
|---|---|---|---|
| 1 | 特定子市場或產品線 | 該子市場的 hub 或工具 | 寫那個工具能做的事 |
| 2 | 是非題 | 是非工具 | 「帶著一個是或否的問題開始」 |
| 3 | 二選一／三選一 | 對應的比較工具 | 寫要比較的兩件事 |
| 4 | 指定流程或模板（案例是牌陣） | 該流程的頁 | 寫流程名 |
| 5 | 單一實體（只偵測到 1 個，且不是總覽頁） | 該實體的正式頁 | 寫實體名 |
| 6 | 情境（例：感情，再細分復合、曖昧） | 情境工具頁 | 寫情境 |
| 7 | 都不符合 | 首頁（依工作、年度、學習換文案） | — |

- **依序比對，先中先得。** 去處必須是站上存在、沒有轉址的頁；`href` 要和去處類型一致（案例有 85 筆子市場 CTA 指錯頁）。
- **「頁面存在」不夠，要「點下去能開始」。** 案例的文章照路由表連到二選一、三選一頁，那兩頁的「開始」按鈕卻都只連回首頁；站上其實只有 3 張的二選一工具，三選一根本不存在。路由表的每個去處，在工具頁改版時和每月內容盤點時各實點一次。
- **文章教的方法要和去處的工具一致**（張數、步驟、位置）。不一致時改文章，或在 CTA 前寫明工具用的是哪一種（`07`）。
- **路由表沒有的去處不要自己發明。** 覺得某篇連到表上沒有的工具更貼題，列成待使用者決定，由使用者決定要不要擴充路由表。
- AI 改寫的 CTA 文字照 `07` §8 的條件驗證，不合格就改用路由表的規則版文案。
- **稽核時先算比例**：CTA 連到首頁或泛用頁的文章占多少。案例 812 篇線上文章有 519 篇（64%）套同一個模板 CTA，按鈕寫站上沒有的功能名，全部連首頁；這是全站成本最低的導流修正。
- 「開始」類的 CTA 照第 5 步：保留功能入口（可帶參數），不先繞到 hub；問題交棒照第 3b 步，不經網址。
- 例（SaaS）：「發票格式」文 → 發票產生器；「A 和 B 比較」文 → 比較頁；其他 → 免費試用頁。

### 6. 共用選單

- 7–10 個核心入口：第一項是首頁的主字（例：「線上○○牌」→首頁），其餘是各工具頁的主字；目前頁加 `aria-current="page"`；手機改成一列可左右滑。下方最多再放 3–4 個相關推薦。
- 競品 T 每頁約 50 個站內連結，但它的主語系只有 36 頁，權重不會被稀釋。大站要學的是「工具頁彼此全連＋關鍵字錨文字＋一句說明」，不是連結數量。
- 共用選單會改到首頁與核心頁的 HTML，照 `03` 算首頁改動，不和其他頁群放同一批。
- 套用方式：預設只列出會改什麼（dry-run），確認後才寫入；只替換標記區塊；保留原檔換行；重跑必須零變更。

### 7. 由關鍵字資料生成落地頁

- 一份頁面清單（manifest）→生成器→同時產出頁面、伺服器路由表、sitemap，三者同源。驗證器檢查清單裡的檔案存在、所有路由都在 sitemap 裡。
- **頁面骨架**：
  1. H1、intro。
  2. 主 CTA 直達工具，次 CTA 到相關文章。
  3. 3 張 H2 卡：適合哪些問題／怎麼問／怎麼用結果。
  4. 4–5 個延伸入口。
  5. 3 題 FAQ，題型例：「{X}準嗎？」「{X}可以問{Y}嗎？」「可以一直重來嗎？」，答案附限制。
  6. 免責聲明。
- **JSON-LD**：Organization、WebSite、WebPage、WebApplication（免費 Offer 只在真的免費時才放）、BreadcrumbList。FAQPage 選用（Google 已不顯示 FAQ 複合式結果）；要放就另放一個 script，題目逐字對應畫面。
- 在生成器裡寫明「一個主字只指派給一頁」，避免兩頁拿到同一組字。
- **介面不能出現技術字樣**。案例的延伸入口區塊直接寫著類似「以下連結為純 HTML 連結，方便搜尋引擎爬取」的說明，使用者看得到。
- **大量產頁的紅線**：Google 把「主要為了操縱排名而大量產頁」列為規模化內容濫用，不管是人寫還是 AI 寫；2026 年的 AI 功能最佳化指南也點名，為 AI 搜尋的衍生查詢（fan-out）大量做頁屬於濫用。生成器上線前檢查：每頁有沒有自己獨有的資料（不只換關鍵字或地名）、同模板頁之間的近似重複率（`content-audit`）、空組合（篩選沒有結果）回真的 404、「已產生」和「可索引」分成兩個狀態、只有核准的頁進 sitemap；分批上線，觀察「已檢索－目前尚未建立索引」的比例。細節見 `15` 第 5 節。
- **開新頁的判斷**：只有在既有頁接不住、而且新網址能長期重複使用時才開。案例的年度頁：既有的「年度運勢」頁一年只有 271 次曝光，帶進來的多是無關查詢；新開「/{年份}/」網址，下一年照同一個模板開，上線當天就有曝光。
- **年度內容的交棒規則**：
  1. 通用的「年度運勢」入口頁不寫年份，免得明年過時；帶年份的內容另開「/{年}/」網址，每年照同一個模板開。
  2. 新年度頁上線時，上一年同主題的頁改成另一個切角（例：「年底回顧這一年的工作與收穫」），並連到新年度頁，避免兩年度互搶同一組字。
  3. 上一年度的頁流量下滑是預期，不放進流失名單（案例：上一年度運勢文每日曝光 3.5→1.0，新年度三篇上線當天就有曝光）。
  4. 新年度頁最晚在媒體開始寫明年度題之前上線（倒推方法見 `12` 步驟 4b 的季節企劃行事曆）；年底前同一頁可以並列「今年剩下的月份」和「明年」，今年的流量才不會在跨年時斷崖。案例的新年度頁比媒體開刊晚了約一個月。

### 8. 功能路由與重複網址

- SPA 功能路由和首頁同一份 HTML 時：canonical 指首頁，一般導覽與一般入口全部改連首頁，帶參數的功能入口保留。不要一口氣全部 301，因為它還負責功能步驟和參數。
- 不存在的路由要回 404＋noindex，不能用 200 回首頁（會變成軟 404、重複首頁）。
- 不支援的語系路徑（例：`/es/`）要 301 到主語系，不能 200 回主語系首頁。
- 舊的 `.html` 網址 301 到無副檔名版本；canonical、sitemap、內鏈、麵包屑、schema 全部指向同一個版本。
- 案例修完這些之後：sitemap 全部網址實測 200、0 轉址、0 noindex。

### 9. 多語與 hreflang

- 所有語系叢集放在同一份設定，HTML 的 alternate 和 sitemap 的 `xhtml:link` 都從這份產生。案例原本散在三個檔案，後來漂移。
- **驗證器強制檢查**：
  - 每頁都有指向自己 canonical 的 self hreflang。
  - `<html lang>` 等於自己的 hreflang。
  - alternate 的目標都是某一頁的 canonical，而且會回指。
  - 目標都在 sitemap 裡，sitemap 和 HTML 一致。
- **爬蟲語言**：沒有語系前綴的網址，要對爬蟲固定回主語系。案例修正前，Googlebot 從美國抓會拿到英文版；這次修正和首頁改定位同批上線，效果無法分開歸因。
- `<html lang>` 在 JS 執行前後要一致。
- 語系版的 SPA 網址被收成獨立頁（原始 HTML 是主語系，JS 才換語言）：導回語系首頁，或設 noindex。
- 薄的語系頁（200–590 字、只有 WebPage schema）幫不上忙。真要做多語，就做在地化的工具頁；競品 T 23 種語言，每種 22–36 頁。

### 10. 變體整併

完整的稽核、評等與整併執行流程見 `08-content-audit-refresh-consolidation.md`；這裡只列架構層面的規則與結果。

先合併網址寫法再判斷：同一頁的 `.html` 與無副檔名版本同時拿曝光，是 canonical 或轉址的技術問題（`10` 步驟 4），不是內容變體（`04` 第 8 步）。

整併規則（實際採用）：

1. 每一頁只能有一種處置：保留升級／合併後 301／保留但 noindex／移除並轉址。
2. 同一意圖只留一個主文；鏈狀或循環轉址一律改指最終主文。
3. 泛用的實體說明頁（「X 代表什麼／完整解析／新手避坑／常見誤區／實戰教學」）一律以正式實體頁為主文；有獨立切角（感情、事業、心理）的才保留。
4. **主文＝品質＋GSC**：同級或只差一級時，若另一頁曝光 ≥3 倍、點擊較多、且曝光 ≥100，就用 GSC 強的網址當主文，把較好的內容搬進去（換內容不換網址）；差兩級以上時品質優先。不為了網址好看，把有流量的網址轉給沒流量的；不拿前三名的網址去換。
5. 只有在點擊與排名都偏向同一頁時才合併；共享查詢的點擊各半時不合併。
6. 主文要先修好才收轉址；導讀 pillar 頁不收轉址。
7. **分波**：
   - 第 0 步：先修主文。
   - 第 1 波：曝光 ≤20 且點擊 ≤2 的空殼，直接轉。
   - 第 2 波：其餘。
   - 第 3 波：曝光 ≥200 或點擊 ≥5 的頁。先逐詞比對主文是否涵蓋它的查詢詞，把獨特段落搬進主文，再轉。
8. **執行**：兩種網址形式（有、無 `.html`）都 301，伺服器邊緣的轉址表也要加；舊網址移出 sitemap、索引頁、`llms-full.txt`；加防回歸測試。舊網址曝光逐步歸零屬預期，不算流失。

案例結果：
- **11 篇同一張牌的變體頁 301 到 2 個主頁**：13 個網址合計曝光 +55%、排名 8.1→7.0、點擊 +10%（期中 10 天）；該牌的「正位」查詢改由正式實體頁接，@6.2。
- **兩篇「怎麼問」重複頁合併**：主頁加舊頁的點擊 283→299，流量保住。
- **全站 828 篇逐篇審稿**：分成 174 群；301 532 篇、原地重寫 11 篇、保留 152 篇。D 級 484 篇平均每篇 28 天只有 56 次曝光。

**非塔羅示意例（電商）**：「{商品} 評價」「{商品} 開箱」「{商品} 優缺點」「{商品} 值得買嗎」四篇互搶，就整併成一篇評測主文；有實際點擊的那篇網址當主文，其他三篇的獨特段落搬進去後再 301。

### 11. 生成器與批次程式的覆寫陷阱

- **雙胞胎檔**：同一路由有兩份實體檔（例：目錄頁和資產副本）。寫入前比對兩份是否逐位元相同，不同就停；寫入時兩份一起寫。
- **標記區塊**：只替換成對標記之間的內容。
- **手動接管標記**：檔頭有「手改，勿重產」就跳過重新生成，只同步雙胞胎。
- **冪等**：找不到目標就報錯，但要先判斷「新值已在、舊值不在＝已套用」；預設 dry-run；保留原檔換行。
- **改任何文案前，先列出所有會寫入這段字的地方。** 同一段字可能從好幾個地方寫進頁面，只改其中一處，下次重產或 JS 執行後就被換回。案例首頁的 title、H1 和說明文字分散在 5 處：
  1. 頁面 HTML（含雙胞胎檔）。
  2. 前端多語字典：JS 執行後會用字典裡的字覆寫 HTML。字典沒改，渲染後看到的還是舊字。
  3. 產生器裡的常數：重跑會用它覆寫首頁。
  4. 獨立的結構化資料檔。
  5. 鎖住現行字串的測試。

  另外要找「會強制改值的後處理腳本」：案例有一支刷新腳本，每次執行都把某個 CTA 連結改回舊網址。改完用 Googlebot UA 同時比對原始 HTML 和渲染後 DOM 的 title、H1、主要段落，兩邊都是新字才算改完。
- **驗收條件**：重新產生後，修正不會被蓋回去。
- **怎麼驗「不會被蓋回」**：先列出會碰到這批頁的腳本（誰觸發、改哪些頁與欄位、會不會跳過人工修過的頁、寫完會不會直接部署）。在整個工作目錄的複本上，依實際上線順序把它們跑一遍，跑完重跑測試，並確認你的腳本再跑一次是零變更。案例的牌義頁改版這樣跑了 6 支腳本才交付。
- **測試失敗先判歸屬**：另開基準版本（上一個正式版）的臨時工作區跑同一組測試；基準版就失敗的，列為既有問題，不要順手改別人的檔。
- **驗證有效的標題與 CTA 寫進回歸測試**：之後產生器把它改掉，部署就會失敗（`09` 第 7 步）。

案例踩過的坑：
- **只改頁面、沒改生成器**：下次產文就被蓋回去。每項修正都要同時改頁面、生成器、刷新腳本和測試。
- **支柱頁比對條件永遠成立**：程式比對兩個不存在的欄位，`undefined === undefined` 恆真，加上過寬的網址比對，每個支柱頁列出 349–584 張卡片，完全失去主題性。
- **假新鮮度**：
  - 頁面寫「更新：建置日」，每次重跑都變。
  - sitemap lastmod 一度 1,037 頁全部是同一天。
  - 有一次整站重產 lastmod，約 890 筆一起變。
  - lastmod 應取「最近一次實質變動」的日期：title、description、robots、canonical、JSON-LD、可見文字（去掉 nav、footer、script）、連結、圖片 src／alt 有變才算；24 小時內被還原的不算。
- **模板內鏈與 CTA 錯**：延伸閱讀錨文字套模板 710 篇；重點摘要照抄描述 534 篇；CTA 連到站上不存在的功能 519 篇（修法見第 5b 步）。
- **硬編碼清單沒和轉址檔對帳**：已經 301 退役的頁，重跑還會被改寫。
- **給 AI 的產文指令變成模板垃圾**：要求「自然提及 2–3 個業界具名實體」，結果 285 篇硬塞同樣的人名 3 次以上。

## 決策規則與門檻

| 規則 | 門檻／做法 |
|---|---|
| 工具頁第一屏 | 第一個輸入框前 ≤約 100 字；3–4 個範例，一點就送出；免費條件寫在按鈕旁、和程式一致 |
| 落地頁承諾 | 無痕、沒登入走一次，逐句對張數、步驟、免費範圍、登入時點 |
| 範例結果 | 正式流程跑一次、第一則就用、只裁不改；和正式服務的差異交使用者決定是否揭露 |
| 內容頁第一屏 | 提問框在手機第一屏（框頂 <844 px）、部署時寫進 HTML、一頁一個；手機底部列不和開場框、結尾 CTA 同時出現 |
| 提問交棒 | 不進網址；sessionStorage 單次、約 10 分鐘有效 |
| CTA 路由 | 全站一份路由表、依序比對；去處存在、沒有轉址、點下去能開始 |
| hub→子頁 | 全部子頁寫在原始 HTML；不靠 JS 或 `#hash` |
| 麵包屑 | 可見、返回總覽、BreadcrumbList 三者都指正式 hub |
| 子頁正文 hub 連結 | 每頁恰好 1 條、在第二個標題前；錨文字 2 種各 ≥30% |
| 入鏈 | 按位置拆開算；上下文入鏈 ≤1 的承接頁先補 |
| 錨文字多樣化 | 情境連結約 1／4 核心詞、1／2 語境描述、1／5 品牌或操作；選單與麵包屑用一致名稱 |
| 改全站錨文字或模板按鈕 | 算受保護頁的改動：單獨一批、記 D0、看護欄 |
| 相關項目 | 每頁 4–7 個；每個實體 ≥3 頁連入 |
| 文章內鏈 | 出站 ≥3、入站 ≥2；每篇補連結 ≤3 條；同一組來源→目標 1 條 |
| 共用選單 | 7–10 個入口＋最多 3–4 個推薦 |
| FAQPage | 選用；結構化資料的每一題都逐字出現在畫面 |
| 大量產頁 | 每頁要有獨有資料；空組合回 404；只有核准的頁進 sitemap；分批上線 |
| 年度內容 | 通用頁不寫年份；帶年份另開 `/{年}/`；舊年度改切角並連到新年度 |
| 改文案 | 先列出所有寫入點（HTML、雙胞胎、多語字典、產生器常數、結構化資料檔、測試、後處理腳本） |
| 整併主文 | 同級或差一級時，曝光 ≥3 倍、點擊較多、曝光 ≥100 的網址當主文 |
| 整併分波 | 第 1 波 ≤20 曝光且 ≤2 點擊；第 3 波 ≥200 曝光或 ≥5 點擊，先搬內容 |
| lastmod | 只在實質變動時更新；24 小時內還原不算 |

## 常見錯誤

- hub 的子頁目錄用 JS 或 `#hash` 產生，Googlebot 看不到，子頁變孤兒。
- 麵包屑指向「學院」「全部文章」這類泛頁，不是正式 hub。
- 只看入鏈總數，不看位置：頁尾、列表分頁撐出來的數字，看起來很多，內文連入卻是 0。
- 錨文字和目的地不符（「○○占卜」連到牌義總覽）。
- 改全站錨文字或模板按鈕時，以為「受保護頁本體沒動」就不算碰到它。
- 為了 SEO 把功能按鈕改成先經過 hub，多一次載入、轉換掉了。
- 提問框用 JS 插在正文中段，就以為「有放了」。
- 把使用者的問題放進網址參數。
- 落地頁寫的和工具實際流程不一樣（張數、免費範圍、要不要登入），或免費條件只寫在 FAQ。
- CTA 只連到首頁，或連到站上不存在、點下去不能開始的功能。
- 手寫範例結果，或挑過、改過再放上頁面。
- 以「新增幾千條連結」當目標，或照抄競品的每頁連結數。
- 一口氣 301 功能路由，把參數和功能步驟弄壞。
- 不存在的路由用 200 回首頁。
- 整併時把有流量的網址轉給沒流量的網址，或拿前三名的網址去換；或把同一頁的 `.html` 雙胞胎當成內容變體。
- 修正只做在頁面上，沒改生成器、刷新腳本、多語字典和測試，下次產文或 JS 執行後就被蓋回去。
- 年度入口頁寫死年份；新年度頁比媒體開刊還晚上線。
- 為了 FAQ 複合式結果加 FAQPage。
- 為了涵蓋更多查詢變體大量產頁。
- 用建置日或檔案修改時間當 lastmod。
- 在介面上寫技術文案（「可被搜尋引擎爬取」）。

## 對應腳本

| 腳本 | 用途 |
|---|---|
| `node scripts/crawl-site.mjs` | 連結圖、入鏈數、錨文字分布、孤兒頁、麵包屑、hreflang、原始 HTML 與渲染後的差異；`--no-sitemap` 量點擊深度；`-text.jsonl` 的非框架連結 |
