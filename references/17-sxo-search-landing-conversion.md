# 17 · 搜尋落地轉換（SXO）：讓搜尋進來的人真的開始用

> 案例站（繁中塔羅占卜工具站）28 天約 8,100 個進站者，只有約四分之一輸入了問題（依清洗口徑 22–27%）。流失最多的一步就是「進站→開始」，其中 7 成落在文章和子市場 hub。
> 把「第一屏提問框＋範例問題＋手機開始列」做對之後，內容頁輸入率 6.7%→11.4%→14.6%（三期各 7 天、入口每期 600–700 人，顯著）。
> SEO 帶來的人不開始用，等於白做；但轉換的升幅也不能算成排名的功勞。這一章教你兩件事都做對。
>
> 這一章是搜尋落地轉換的總綱：為什麼要做、怎麼量、先做什麼、怎麼驗收。頁面上的做法（第一屏提問框、範例題、hub 表單、交棒、手機開始列、CTA 路由表、落地頁承諾）寫在 `06` 第 3、3b、5、5b 步；CTA 前後文案與語氣的審稿規則在 `07`；排名與點擊怎麼驗收在 `02`。

## 何時使用

- 自然流量漲了，開始使用、註冊、付費沒有跟著漲。使用者說「流量有了但沒人用」時先來這一章，不要先去改 title 或加文章。
- 要改落地頁的第一屏、CTA、提問框、範例問題、免費條件說明、登入時機、付費牆時機。
- 驗收時要回答「搜尋進來的人有沒有開始用」。
- 文章、詞條、hub 這類內容頁很多，帶進來的人卻幾乎不碰產品。

## 步驟

### 步驟 1：先分類：這項改動是「SEO 增長」還是「SXO 轉換」

- 能提升自然曝光、點擊、CTR、索引訊號的，算 **SEO 增長**，用 GSC 驗收（`02`）。
- 只提升進站後的開始、完成、註冊的，算 **SXO 轉換**，用自然搜尋 session 的轉換驗收（本章步驟 2）。CTA、提問框、範例問題、登入位置、免費條件文案、付費牆時機都屬這一類。
- 轉換的升幅不能寫成排名的功勞；反過來，GSC 點擊沒變，也不代表轉換類改動無效。案例的 CTA 深連結那一波，全站點擊持平（每週 1,145→1,167），自然搜尋拿到完整結果的 session 卻明顯增加（一份分析是 48→70，另一份 28 天口徑是 +61%；都是前後比，同期有量測斷點）。當時它和摘要改寫放在同一波、用 GSC 判，被寫成「無效」，後來才更正（`14`）。
- 轉換類改動也要登記成一波、單獨記 D0（`03` 步驟 1；`log-change add --type non-seo-change`）。它常一次改到幾百頁的 HTML（案例深連結約 860 頁、文案約 289 頁），會汙染同期 SEO 波次的對照組；把這些頁列進那些波次的「所在觀察窗」。
- GA4 有量測斷點時，前後比只寫「被記錄的轉換增加」，不寫成已證實的成長。

### 步驟 2：量對：自然搜尋、同一個 session、按入口類型

1. **只算自然搜尋的 session，轉換要在同一個 session、落地之後發生。** 用 BigQuery 以 `user_pseudo_id`＋`ga_session_id` 串（範本在文末）。來源用 session 層級：主口徑 A 看 session 開頭的來源標記（沒有就看落地 referrer），口徑 B 用 `session_traffic_source_last_click` 對照；兩者方向一致才下結論（`02` 步驟 6）。不用「首次使用者來源」。
2. **按入口類型各列一行**：工具頁、首頁、hub、文章、實體頁。案例 28 天的基準（已排除機器人；「進站→開始」／「進站→完成」）：

   | 入口類型 | 進站→開始 | 進站→完成 |
   |---|---|---|
   | AI 工具頁 | 65% | 17% |
   | 是非工具頁 | 60% | 9% |
   | 首頁 | 43% | 9% |
   | 子市場 hub | 26% | 9% |
   | 文章 | 12.5% | 3.3% |
   | 實體頁（牌義） | 1.7% | 0.2% |

3. **「完成」用一組事件的聯集定義**（例：完成、登入後解鎖、回站恢復），去重後要求發生在前一步之後。新增事件（例：「在內容頁開始提問」）後，另算一個只用舊事件的同口徑版本（案例 6.7%→9.5%→12.8%），不要把新事件的計數當成提升。
4. **分來源看，不要混成一個平均。**
   - 首頁改定位搶到泛字（同一天也把手機開始按鈕固定在第一屏）後，全來源的首頁輸入率 33%→46%，只看自然搜尋卻是 60%→48%（50→233 人）：泛字帶進來的人意圖比較弱，全來源的升幅主要來自付費社群與直接流量。
   - CTA 深連結那一波，一份前後比分析裡全來源的內容頁輸入率 10.2%→8.6%，看起來失敗；只看自然搜尋 session 是 25.0%→26.7%。同期某國桌機 Direct 從 1,436 個 session 漲到 2,183，有輸入的只有 2→0 個。（不同分析的口徑不同，數字不能互相換算。）
   - 付費社群、直接流量、低互動來源（異常國家＋桌機＋Direct）各列一行。
5. **先清洗再比**（細節與門檻見 `02` 步驟 6）：高頻瀏覽器（同一瀏覽器 7 天輸入或完成 ≥20 次，另用 ≥50 做敏感度）、內部與測試帳號（伺服器端資料也要排除）、付費流量、爆量週、非正式網域；營收集中在少數老客戶時並列「含／不含」。兩種清洗口徑的數字並列（案例只影響第一步分母：21.7% 對 26.9%）。
6. **報告一定寫口徑。** 案例首頁的開始率，在不同報告裡出現過 16%、32%、37%、43%、46%、48%、52%、60%、62%：差別全在來源、清洗、新舊訪客、session 定義與期間。沒寫口徑的開始率不能拿來比。
7. **改了 CTA 目的地，落地頁會搬家**：例如文章按鈕從功能路由改成首頁，首頁開始率要用兩頁合計，或從 D+1（部署隔天）起重取基準。
8. **註冊數、預覽數和流量同幅下降時，是流量問題，不是轉換變差。**
9. **轉換貢獻表**（每月或每波）：每個落地頁群列「自然 session 占比｜開始占比｜開始率」。兩個占比差很多的頁群，就是要先修的地方。案例某一期：文章占自然 session 47%，只占開始的 18%。
10. **量測缺口先補**：某頁型沒送落地事件，就不能拿它判 CTA 無效（`01` 第 7 節的案例只有約 9% 的落地帶事件）。事件設計（`placement` 參數、交棒不經網址）見 `01` 第 3 節。

### 步驟 3：依意圖分流，不要用同一把尺

- **知識型頁**（牌義、詞條、商品規格）：案例實體頁幾乎沒人開始用（1.7%），卻是停留最久的頁（每人約 110 秒、41% 捲到 90%）。讀者是來查資料的；它的任務是被搜到、被引用、把需要的人導到工具頁。不要用轉換率判它好壞。
- **意圖混合、量又大的頁**（文章、hub）：SXO 的力氣先花在這裡。案例「進站卻沒開始」的人有 7 成落在這兩類。
- **工具頁**：守住第一屏（`06` 第 3 步），盯開始率不下降。
- **工具意圖的查詢落在文章上**：照 `04` 第 7 步規則 8，在文章第一段放一條明顯的工具頁連結，讓讀者不用讀完才找得到入口；不要把文章改寫成工具頁，也不要讓文章 title 去搶工具頁的主字。案例一篇教學文在接「感情占卜」這類大字（排 12–20 名）。
- **內容語氣不要拆掉產品的核心動作**（審稿規則在 `07`）：案例全站的首頁 FAQ、工具頁、hub、文章都在勸「不要短時間重複占卜」，等於拆掉「追問、再問一題」的理由；轉換診斷把它列為付費理由不足的原因之一。

### 步驟 4：做法（依成本由低到高；頁面上怎麼做在 `06`）

| 順序 | 做法 | 頁面上怎麼做 | 案例 |
|---|---|---|---|
| 1 | CTA 直接開到對應的工具流程（深連結），全站照一份 CTA 路由表 | `06` 第 5 步（功能入口不繞路）、第 5b 步（依序比對、點下去要能開始、文章方法和工具一致） | 812 篇文章有 519 篇的 CTA 全連首頁；改經過 hub 會多一次載入，手機從按鈕到送出 2.96→3.47 秒 |
| 2 | CTA 連同前後兩句一起審：讀者以為點下去能做到的事，站上要真的做得到 | `07`（CTA 和前後文字構成承諾） | 「全攤 36 張」後面接「到線上抽牌」，站上只有 5 張和 9 宮格 |
| 3 | 內容頁第一屏提問框：部署時寫進 HTML、一頁一個 | `06` 第 3b 步第 1 點 | JS 事後插入時落在 2,300–6,700 px，之後兩週 7.2%→7.6%；改成部署時寫入第一屏後，文章 7.8%→17.7%、實體頁 1.4%→4.7%（前後比） |
| 4 | 範例問題一點就送出、每頁自己的題目 | `06` 第 3 步第 3 點 | 讀者幾乎不打字；28 天約 8,100–8,300 人（依清洗口徑）只有約四分之一開始 |
| 5 | 入口頁（hub）的 hero 就是表單，給不想打字的人「直接開始」 | `06` 第 3 步第 3 點 | 子市場 hub，以及 AI、是非、神諭入口頁 |
| 6 | 手機底部開始列：捲過開場框才出現，到文末 CTA 讓開 | `06` 第 3b 步第 3 點 | — |
| 7 | 提問交棒不經網址（同分頁 `sessionStorage`，讀一次就刪） | `06` 第 3b 步第 2 點；量測面見 `01` 第 3.2 節 | — |
| 8 | 長頁的中段和頁尾也要有入口（按鈕或連結，不是第二個提問框） | 本節 | 一個 hub 從第一屏到最後一屏之間沒有任何入口，GA4 平均每人只停 8 秒；另一個工具頁頁尾沒有入口 |

- **先修最便宜的**：CTA 路由只改連結與文案，通常是全站成本最低的導流修正；第一屏入口、範例題、開始列是頁面元件，要寫瀏覽器測試（`06` 第 3b 步）。
- **一頁只放一個提問框**：讀完才想試的人，由手機開始列和文末 CTA 接住（案例最後拿掉了文末的第二個框）。
- **每個入口都用 `placement` 區分**（開場框、hub hero、底部列、文末 CTA），才分得出哪個入口有用（`01` 第 3.1 節）。
- **每一項都是轉換改動**：照步驟 1 登記成一波、記 D0，照步驟 7 驗收；全站套用前，先在一個頁群試。

### 步驟 5：落地頁的承諾要等於實際流程

- **用無痕視窗、沒登入，把落地頁的每一句承諾和實際流程逐句對**（做法在 `06` 第 3 步第 4 點）：張數、步驟、看得到多少、要不要登入、空白能不能送出、之後要付什麼。條件寫在輸入框或主按鈕旁，照事實表（`07`），不要只放在 FAQ。
  - 案例的是非工具頁寫「抽一張牌」，按鈕卻進通用流程；那段期間這頁自然落地輸入率 76%→44%。
  - 子市場落地頁寫三張、工具抽五張；淺色落地頁一按就跳到深色工具頁，會讓人以為跑到別的網站；選了範例題還要再按一次開始。這些都會掉人。
- **登入放在看到價值之後**（`06` 第 3 步第 4 點）：案例改成「展開完整結果」時才登入後，完成率 74%→90%（差異顯著，但同一天也改了鎖卡版面，歸因是推測）。多加一種第三方登入，前 5 天只看到它分走既有方式的解鎖（11 人，待觀察），不要預期它會多出使用者。
- **範例結果要可稽核**（`06` 第 3 步第 7 點）：手寫的「範例結果」等於另一種假見證。
- **工具結果頁不要再掛整段首頁的 SEO 文字與 FAQ**：案例的結果頁因此拉長到 4,580px，鎖卡和分享卡也在搶注意力。

### 步驟 6：搜尋進來的人只在當下決定：免費條件、登入、付費牆

- 案例：看到預覽後會點解鎖的人，94% 在 2 分鐘內就點；看到付費提示後會去結帳的人，73% 在 2 分鐘內；新使用者隔天回來的只有 2–4%。
- 所以轉換機會幾乎只在第一次造訪：把開始的入口放在落地頁上，不要指望他們回訪。
- 免費條件和價格要在入口附近寫清楚（照事實表），不要只放在 FAQ。寫上去之後照步驟 7 盯開始率：案例首頁在問題框下加了一段免費條件說明後，開始率 52%→32%，但入口只有 28 人、同期又有付費規則改動，判「待觀察、方向偏退步」，並單獨檢查那段說明。
- **免費額度、付費牆時機、資格檢查的位置，都是 SEO→產品指標的斷點。** 單獨記 D0、和 SEO 批次錯開；之後的「完整結果」和回訪 cohort 不和改動前比（`02` 步驟 6）。
  - 除了付費，另外盯四個代價指標：解鎖（或註冊）率、第一天繼續使用率、隔天與 7 天回訪、「註冊後完全沒使用」的比例。案例付費牆提前後，碰牆比例 10.6%→23.6%、解鎖率持平，但新帳號第一天繼續使用 58%→41%（p=0.01），「註冊後完全沒使用」1.6%→9.5%（p=0.01）；付費 0/124→2/105，樣本不足。
  - 資格檢查（額度、登入）往前移，漏斗前段會看起來退步、後段失敗變少，其實只是攔截點換了位置。把檢查結果做成聚合事件（可以開始／額度不足／需要登入／檢查失敗），分母用「可以開始」的人。
- **要不要讓第一次免登入就看完整結果：當產品試驗做，不當 SEO 必做。** 成本假設、試驗設計、分母與驗收照 `06` 第 3 步。兩個最常犯的錯：把「完整內容被看的次數」增加當成功（那是規則改了的直接結果）；付費樣本不足時就下結論（應該維持「未定論」）。

### 步驟 7：上線與驗收

- **每一波都加一條產品護欄**：該頁群自然落地 session 的開始率與互動率不得下降，新訪客、回訪者分開列（`03` 步驟 3 第 5 點；`templates/wave-record.md` 第 5 節）。
- **判讀門檻**：≥7 個完整日、入口 ≥30 人，Fisher p<0.05 才寫進步或退步（`rate-test`）；不到門檻寫「待觀察」，下一週重看。
- **不要用 3 天判**：案例上線 3 天的報告寫「提問框看不出效果」，當時 hub 入口也從 7 天 1,023 人掉到 3 天 57 人（爆量剛結束），組成變了；滿兩個完整週後是顯著進步。
- **新增事件後**，另算一個只用舊事件的同口徑版本（步驟 2 第 3 點）。
- **改了入口按鈕的目的地**：分母會搬家，合併計算，或從 D+1（部署隔天）起重取基準。
- **曝光回來、使用者卻做不完主要動作時**，先修產品體驗，不要再改標題。
- **為了 SEO 讓使用者多走一頁或多讀一段**，就算排名進步，也可能得不償失（文章按鈕改經過 hub，手機到送出 2.96→3.47 秒）。
- 報告的產品端表格照 `templates/review-report.md` 第 11 節，依入口類型分列。

### 步驟 8：站外引用帶來的人做了什麼

- 每 4 週的外聯小結，除了參照流量，也依類別和到達網頁看參與工作階段、核心動作完成數、註冊數（只記錄、不設目標；`12`）。
- 要不要加碼，看哪一類真的帶來會用產品的人。只看流量量，會加碼到帶不來使用者的類別。

## 決策規則與門檻

| 項目 | 規則 |
|---|---|
| 分類 | 每項改動先標「SEO 增長」或「SXO 轉換」，各用各的指標驗收；轉換升幅不算排名功勞 |
| 口徑 | 只算自然搜尋 session（A 為主、B 對照）；同一 session、落地之後；按入口類型與來源分列；先清洗再比；報告寫明口徑 |
| 完成 | 一組事件的聯集，去重、要在前一步之後；新增事件另算舊口徑 |
| 知識型頁 | 不用轉換率判；任務是被搜到、被引用、導到工具 |
| CTA | 照全站一份路由表依序比對（`06` 第 5b 步）；去處存在、沒有轉址、點下去能開始、方法一致；不要自己發明去處 |
| 第一屏 | 文章、實體頁、hub 的第一屏都要有入口（部署時寫進 HTML，不靠 JS 事後插入）；範例問題一點就送出；手機有開始列；提問框一頁一個（`06` 第 3、3b 步） |
| 承諾 | 落地頁寫的張數、步驟、免費範圍、登入時機＝匿名訪客的實際流程；條件寫在按鈕旁（`06` 第 3 步第 4 點） |
| 隱私 | 使用者輸入不經網址傳遞；分析事件只帶列舉值 |
| 判讀 | ≥7 個完整日、入口 ≥30 人、Fisher p<0.05；不用 3 天判；付費者 <4–5 人寫「樣本不足」 |
| 護欄 | 每一波都有「自然落地開始率不得下降」 |
| 斷點 | 免費額度、付費牆時機、資格檢查位置：單獨記 D0，盯代價指標，之後的 cohort 不和改動前比 |

## 常見錯誤

1. **用全來源平均判 SXO**：機器人與付費流量會把結論翻過來（全來源 10.2%→8.6%，自然搜尋 25.0%→26.7%）。
2. **拿知識型頁的低轉換率判它「沒用」**。
3. **提問框放在正文中段，或用 JS 事後插入，就以為「有放了」**：案例第一版落在 2,300–6,700 px。
4. **用上線 3 天的資料宣布「沒效果」**。
5. **把使用者的問題放進網址參數**。
6. **落地頁寫的和工具實際做的不一樣**（張數、免費範圍、要不要登入）。
7. **把轉換的升幅寫成 SEO 的功勞，或把 GSC 點擊持平寫成轉換改動無效**。
8. **CTA 連到不存在的功能，或連到「存在但點下去不能開始」的頁**：案例 519 篇文章的 CTA 全連首頁；改連二選一、三選一頁之後，才發現那兩頁的按鈕也只回首頁。
9. **範例問題點了只會填進輸入框**：讀者幾乎不打字。
10. **把新事件的計數當成提升**。
11. **沒寫口徑就報開始率**：同一個首頁，報告裡出現過 16%～62%。
12. **內容語氣勸退產品的核心動作**：全站勸「不要重複占卜」，等於拆掉「追問、再問一題」。
13. **手寫範例結果**：等於另一種假見證。

## 範本

**BigQuery：自然搜尋 session 的「進站→開始」（按入口類型）**

```sql
-- 對照口徑 B（session_traffic_source_last_click）。主口徑 A 要改用 session 開頭的來源標記與落地 referrer（`02` 步驟 6）。
-- 只讀日表：events_* 加上 _TABLE_SUFFIX 日期範圍，會自動排除 events_intraday_*。
-- 清洗（高頻瀏覽器、內部帳號、非正式網域）照 `02` 步驟 6，在 landing 加條件排除。
-- 完成率：把 started 裡的事件換成完成事件的聯集（例：IN ('tool_completed', '<解鎖完成>')），並要求發生在開始之後。
WITH ev AS (
  SELECT
    user_pseudo_id,
    (SELECT value.int_value FROM UNNEST(event_params) WHERE key = 'ga_session_id') AS sid,
    event_name,
    event_timestamp,
    (SELECT value.string_value FROM UNNEST(event_params) WHERE key = 'surface') AS surface,
    session_traffic_source_last_click.cross_channel_campaign.default_channel_group AS channel
  FROM `<專案>.<資料集>.events_*`
  WHERE _TABLE_SUFFIX BETWEEN '20261001' AND '20261028'
),
landing AS (  -- 每個 session 的第一個落地事件；沒送 seo_landing_view 的頁型在這裡看不到，先補量測
  SELECT
    user_pseudo_id,
    sid,
    MIN(event_timestamp) AS landing_ts,
    ARRAY_AGG(IFNULL(surface, '(未標)') ORDER BY event_timestamp LIMIT 1)[OFFSET(0)] AS entry_type,
    ANY_VALUE(channel) AS channel
  FROM ev
  WHERE event_name = 'seo_landing_view' AND sid IS NOT NULL
  GROUP BY user_pseudo_id, sid
),
started AS (  -- 同一 session、落地之後的開始
  SELECT DISTINCT l.user_pseudo_id, l.sid
  FROM landing l
  JOIN ev e
    ON e.user_pseudo_id = l.user_pseudo_id
   AND e.sid = l.sid
   AND e.event_name = 'tool_start'
   AND e.event_timestamp > l.landing_ts
)
SELECT
  l.entry_type,
  COUNT(*) AS organic_sessions,
  COUNT(s.sid) AS started_sessions,
  ROUND(SAFE_DIVIDE(COUNT(s.sid), COUNT(*)), 4) AS start_rate
FROM landing l
LEFT JOIN started s USING (user_pseudo_id, sid)
WHERE l.channel = 'Organic Search'
GROUP BY l.entry_type
ORDER BY organic_sessions DESC;
```
